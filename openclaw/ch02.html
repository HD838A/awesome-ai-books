概述

本章深入探讨 ACP（Agent Communication Protocol）协议的设计原理。ACP 是 OpenClaw 中 Agent 之间以及 Agent 与外部系统通信的基础协议。

2.1 为什么需要 ACP 协议

💡 类比：想象你要设计一个"推送通知系统"。你当然可以用轮询（每 5 秒请求一次）来实现，但为什么不直接用 APNs？因为 APNs 是为推送场景专门设计的——它知道什么是设备令牌、什么是优先级、什么是静默推送。ACP 也是如此——它是专门为 Agent 通信场景设计的。
需求 HTTP 的局限 ACP 的优势
流式响应 需要 SSE 或 WebSocket 原生支持流式 Delta
长时间运行 需要轮询或 WebSocket 内置运行状态追踪
工具调用 需要手动设计 JSON-RPC 内置权限和审批流程
多 Agent 协作 需要额外设计协议 会话和消息自动管理

2.2 ACP 协议基础

消息格式

ACP 使用 NDJSON（Newline Delimited JSON）格式传输消息——每行一个 JSON 对象：

{"type": "start", "sessionId": "abc-123"}
{"type": "delta", "content": "Hello"}
{"type": "delta", "content": ", world!"}
{"type": "end", "result": "completed"}
💡 类比：NDJSON 类似于 iOS 中的 Combine 框架的 PassthroughSubject——每次 send() 就输出一行。但 Combine 是内存中的数据流，NDJSON 是可以持久化和网络传输的。

2.3 本章小结

概念 关键点
ACP vs HTTP ACP 原生支持流式、工具调用、多 Agent
NDJSON 每行一个 JSON 对象的流式格式
会话管理 有状态的会话支持双向通信
策略控制 内置权限和审批流程
