11.1 案例一：团队协作——架构师→开发者→审查员

11.1.1 场景

一个开发团队需要完成一个新功能：

  1. 架构师：设计 API 契约和文件结构
  2. 开发者：根据设计实现代码
  3. 审查员：审查代码并给出反馈

11.1.2 代码实现

import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'
import type { AgentConfig, OrchestratorEvent } from '@jackchen_me/open-multi-agent'

const architect: AgentConfig = {
  name: 'architect',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个软件架构师，精通 Node.js 和 REST API 设计。
你的输出是简洁的技术规范（markdown 格式）。
聚焦于接口、数据结构和文件结构。保持简洁。`,
  tools: ['bash', 'file_write'],
  maxTurns: 5,
  temperature: 0.2,
}

const developer: AgentConfig = {
  name: 'developer',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个 TypeScript/Node.js 开发者。
你根据架构师的设计实现代码。将文件写入 /tmp/team-output/。
使用工具完成工作。`,
  tools: ['bash', 'file_read', 'file_write', 'file_edit'],
  maxTurns: 12,
  temperature: 0.1,
}

const reviewer: AgentConfig = {
  name: 'reviewer',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个资深代码审查员。
审查代码的正确性、安全性和可读性。
提供结构化审查：LGTM、建议、问题。`,
  tools: ['bash', 'file_read', 'grep'],
  maxTurns: 5,
  temperature: 0.3,
}

// 进度追踪
const startTimes = new Map<string, number>()

function handleProgress(event: OrchestratorEvent): void {
  const ts = new Date().toISOString().slice(11, 23)

  switch (event.type) {
    case 'agent_start':
      startTimes.set(event.agent ?? '', Date.now())
      console.log(`[${ts}] AGENT START  → ${event.agent}`)
      break

    case 'agent_complete': {
      const elapsed = Date.now() - (startTimes.get(event.agent ?? '') ?? Date.now())
      console.log(`[${ts}] AGENT DONE   ← ${event.agent} (${elapsed}ms)`)
      break
    }

    case 'task_start':
      console.log(`[${ts}] TASK START   ↓ ${event.task}`)
      break

    case 'task_complete':
      console.log(`[${ts}] TASK DONE    ✓ ${event.task}`)
      break
  }
}

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
  onProgress: handleProgress,
})

const team = orchestrator.createTeam('dev-team', {
  name: 'dev-team',
  agents: [architect, developer, reviewer],
  sharedMemory: true,
})

const tasks = [
  {
    title: '设计 API',
    description: '为一个 TODO 应用设计 REST API。列出端点、数据结构和文件结构。',
    assignee: 'architect',
  },
  {
    title: '实现代码',
    description: '根据架构师的设计，实现 TODO 应用的 TypeScript 代码。',
    assignee: 'developer',
    dependsOn: ['设计 API'],
  },
  {
    title: '代码审查',
    description: '审查开发者写的代码，给出改进建议。',
    assignee: 'reviewer',
    dependsOn: ['实现代码'],
  },
]

await orchestrator.runTasks(team, tasks)

11.2 案例二：Fan-Out / Aggregate（多视角分析）

11.2.1 场景

分析一个商业决策时，需要同时考虑多个视角：

  • 乐观分析师：看机会和趋势
  • 怀疑分析师：看风险和挑战
  • 务实分析师：看执行可行性

最后由综合分析师汇总所有观点，得出结论。

11.2.2 代码实现

import { Agent, AgentPool, ToolRegistry, ToolExecutor, registerBuiltInTools } from '@jackchen_me/open-multi-agent'
import type { AgentConfig, AgentRunResult } from '@jackchen_me/open-multi-agent'

const TOPIC = `一个独立开发者是否应该构建使用 AI Agent 的 SaaS 产品？`

// 三个分析师 Agent
const optimistConfig: AgentConfig = {
  name: 'optimist',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个乐观的技术分析师，关注机会、上升潜力和新兴趋势。
你看到可能性而不是障碍。用具体推理支持你的乐观态度——
引用市场趋势、成本曲线和实际能力。保持分析在 200-300 字。`,
  maxTurns: 1,
  temperature: 0.4,
}

const skepticConfig: AgentConfig = {
  name: 'skeptic',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个怀疑的技术分析师，关注风险、挑战和隐藏成本。
你压力测试假设并问"什么可能出错？"
用具体推理支持你的怀疑——
引用失败率、技术限制和市场现实。保持分析在 200-300 字。`,
  maxTurns: 1,
  temperature: 0.4,
}

const pragmatistConfig: AgentConfig = {
  name: 'pragmatist',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个务实的技术分析师，关注实际可行性、执行复杂性和资源需求。
你关心今天什么有效，而不是什么可能有一天有效。
你用 MVP、时间线和具体权衡来思考。保持分析在 200-300 字。`,
  maxTurns: 1,
  temperature: 0.4,
}

const synthesizerConfig: AgentConfig = {
  name: 'synthesizer',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个资深战略顾问，综合多个观点形成平衡、可操作的建议。
不要只是总结——你要权衡论点，找出共识和分歧，
给出明确结论和下一步行动。结构化输出：
1. 各观点的共识
2. 分歧点及你的权衡
3. 结论（做 / 不做 / 有条件做）
4. 建议的下一步（3-5 点）`,
  maxTurns: 1,
  temperature: 0.3,
}

function buildAgent(config: AgentConfig): Agent {
  const registry = new ToolRegistry()
  const executor = new ToolExecutor(registry)
  return new Agent(config, registry, executor)
}

const optimist    = buildAgent(optimistConfig)
const skeptic     = buildAgent(skepticConfig)
const pragmatist  = buildAgent(pragmatistConfig)
const synthesizer = buildAgent(synthesizerConfig)

// 构建 AgentPool（最多 3 个并发）
const pool = new AgentPool(3)
pool.add(optimist)
pool.add(skeptic)
pool.add(pragmatist)
pool.add(synthesizer)

// Step 1: Fan-out — 并行分析
console.log('📊 多视角分析')
console.log('='.repeat(60))
console.log(`\n主题: ${TOPIC}\n`)

const fanOutResults = await pool.runParallel([
  { agent: 'optimist',   prompt: `从乐观角度分析：${TOPIC}` },
  { agent: 'skeptic',    prompt: `从怀疑角度分析：${TOPIC}` },
  { agent: 'pragmatist', prompt: `从务实角度分析：${TOPIC}` },
])

console.log('\n各分析师结论：')
for (const [name, result] of fanOutResults) {
  console.log(`\n[${name.toUpperCase()}]`)
  console.log(result.output.slice(0, 200) + '...')
}

// Step 2: Aggregate — 综合报告
const allAnalyses = Array.from(fanOutResults.entries())
  .map(([name, result]) => `## ${name}\n${result.output}`)
  .join('\n\n')

const synthesisResult = await synthesizer.run(
  `基于以下三个视角的分析，给出综合建议：\n\n${allAnalyses}`
)

console.log('\n' + '='.repeat(60))
console.log('📝 综合报告')
console.log('='.repeat(60))
console.log(synthesisResult.output)

11.2.3 MapReduce 模式图

┌─────────────────────────────────────────────────────────────────┐
│                        MAP (Fan-Out)                             │
│                                                                 │
│    TOPIC ──┬──► [optimist]   ──► 分析报告 A                    │
│            ├──► [skeptic]    ──► 分析报告 B                    │
│            └──► [pragmatist] ──► 分析报告 C                    │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                        REDUCE (Aggregate)                        │
│                                                                 │
│  [报告 A] ─┐                                                    │
│  [报告 B] ─┼──► [synthesizer] ──► 综合报告                      │
│  [报告 C] ─┘                                                    │
└─────────────────────────────────────────────────────────────────┘

11.2.4 关键解析

为什么用 MapReduce？

  1. 并行化：三个分析师同时工作，速度是顺序的 3 倍
  2. 多角度：不同视角的分析更加客观全面
  3. 综合：最终报告考虑了所有角度，避免单一视角偏见

11.3 案例三：带重试的数据获取流水线

11.3.1 场景

数据获取可能因为网络问题失败，需要：

  1. 配置重试机制
  2. 显示重试进度
  3. 最终汇聚结果

11.3.2 代码实现

import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'
import type { AgentConfig, OrchestratorEvent } from '@jackchen_me/open-multi-agent'

const fetcher: AgentConfig = {
  name: 'fetcher',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个数据获取 Agent。
给定一个主题，产生一个简短的 JSON 摘要，包含 3-5 个关键事实。
只输出有效的 JSON，不要 markdown fences。
示例：{"topic":"...","facts":["fact1","fact2","fact3"]}`,
  maxTurns: 2,
}

const analyst: AgentConfig = {
  name: 'analyst',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个数据分析师。
从共享内存读取获取的数据，产生简短分析（3-4 句），突出趋势或洞察。`,
  maxTurns: 2,
}

// 重试进度处理
function handleProgress(event: OrchestratorEvent): void {
  const ts = new Date().toISOString().slice(11, 23)

  switch (event.type) {
    case 'task_start':
      console.log(`[${ts}] TASK START    "${event.task}" (agent: ${event.agent})`)
      break

    case 'task_complete':
      console.log(`[${ts}] TASK DONE     "${event.task}"`)
      break

    case 'task_retry': {
      const d = event.data as {
        attempt: number
        maxAttempts: number
        error: string
        nextDelayMs: number
      }
      console.log(`[${ts}] TASK RETRY    "${event.task}"`)
      console.log(`              尝试 ${d.attempt}/${d.maxAttempts}, ${d.nextDelayMs}ms 后重试`)
      console.log(`              错误: ${d.error.slice(0, 120)}`)
      break
    }

    case 'error':
      console.log(`[${ts}] ERROR         "${event.task}" agent=${event.agent}`)
      break
  }
}

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
  onProgress: handleProgress,
})

const team = orchestrator.createTeam('retry-demo', {
  name: 'retry-demo',
  agents: [fetcher, analyst],
  sharedMemory: true,
})

const tasks = [
  {
    title: '获取数据',
    description: '获取关于 TypeScript 最新特性的 JSON 数据',
    assignee: 'fetcher',
    maxRetries: 3,       // 最多重试 3 次
    retryDelayMs: 1000,   // 基础延迟 1 秒
    retryBackoff: 2,       // 指数退避
  },
  {
    title: '分析数据',
    description: '分析获取的数据，识别关键趋势',
    assignee: 'analyst',
    dependsOn: ['获取数据'],
  },
]

await orchestrator.runTasks(team, tasks)

11.4 案例四：全链路追踪观测

11.4.1 场景

一个完整的多 Agent 项目，需要：

  1. 全链路追踪（每个 LLM 调用、工具调用）
  2. Token 消耗统计
  3. 成本计算
  4. 输出可读的追踪报告

11.4.2 代码实现

import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'
import type { AgentConfig, TraceEvent } from '@jackchen_me/open-multi-agent'

const researcher: AgentConfig = {
  name: 'researcher',
  model: 'claude-sonnet-4-6',
  systemPrompt: '你是一个研究助手，提供简洁、准确的答案。',
  maxTurns: 2,
}

const writer: AgentConfig = {
  name: 'writer',
  model: 'claude-sonnet-4-6',
  systemPrompt: '你是一个技术作家，将研究总结为清晰的说明文字。',
  maxTurns: 2,
}

// 追踪统计
const stats = {
  llmCalls: 0,
  toolCalls: 0,
  totalInputTokens: 0,
  totalOutputTokens: 0,
  agentDurations: new Map<string, number>(),
  taskDurations: new Map<string, number>(),
}

function handleTrace(event: TraceEvent): void {
  const dur = `${event.durationMs}ms`.padStart(7)

  switch (event.type) {
    case 'llm_call':
      stats.llmCalls++
      stats.totalInputTokens  += event.tokens?.input_tokens ?? 0
      stats.totalOutputTokens += event.tokens?.output_tokens ?? 0
      console.log(
        `[LLM]  ${dur} agent=${event.agent} model=${event.model}` +
        ` turn=${event.turn} tokens=${event.tokens.input_tokens}in/${event.tokens.output_tokens}out`
      )
      break

    case 'tool_call':
      stats.toolCalls++
      console.log(
        `[TOOL] ${dur} agent=${event.agent} tool=${event.tool}` +
        ` error=${event.isError}`
      )
      break

    case 'task':
      stats.taskDurations.set(event.taskTitle ?? event.task ?? '', event.durationMs)
      console.log(
        `[TASK] ${dur} task="${event.taskTitle ?? event.task}"` +
        ` agent=${event.agent} success=${event.success} retries=${event.retries}`
      )
      break

    case 'agent':
      stats.agentDurations.set(event.agent, event.durationMs)
      console.log(
        `[AGNT] ${dur} agent=${event.agent} turns=${event.turns}` +
        ` tools=${event.toolCalls}`
      )
      break
  }
}

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
  onTrace: handleTrace,
})

const team = orchestrator.createTeam('trace-demo', {
  name: 'trace-demo',
  agents: [researcher, writer],
  sharedMemory: true,
})

const tasks = [
  { title: '研究', description: '列出 TypeScript 对大型代码库的 5 个关键优势。保持简洁。', assignee: 'researcher' },
  { title: '写作', description: '读取共享内存中的研究，写一个 3 句的总结。', assignee: 'writer', dependsOn: ['研究'] },
]

console.log('追踪观测示例')
console.log('='.repeat(60))
console.log('流水线: research → write (全链路追踪)')
console.log('='.repeat(60))
console.log()

await orchestrator.runTasks(team, tasks)

// 成本报告
console.log('\n' + '='.repeat(60))
console.log('📊 执行报告')
console.log('='.repeat(60))
console.log(`🔢 LLM 调用: ${stats.llmCalls}`)
console.log(`🔧 工具调用: ${stats.toolCalls}`)
console.log(`📝 Token 总量: ${stats.totalInputTokens.toLocaleString()} in / ${stats.totalOutputTokens.toLocaleString()} out`)

console.log('\n⏱ 各任务耗时:')
for (const [task, dur] of stats.taskDurations) {
  console.log(`  ${task}: ${dur}ms`)
}

console.log('\n⏱ 各 Agent 耗时:')
for (const [agent, dur] of stats.agentDurations) {
  console.log(`  ${agent}: ${dur}ms`)
}

// 成本估算 (Claude Sonnet: $3/MTok in, $15/MTok out)
const inputCost  = (stats.totalInputTokens  / 1_000_000) * 3
const outputCost = (stats.totalOutputTokens / 1_000_000) * 15
console.log(`\n💰 成本估算: $${(inputCost + outputCost).toFixed(4)}`)
console.log(`  (输入 $${inputCost.toFixed(4)} + 输出 $${outputCost.toFixed(4)})`)

11.5 模式选择指南

场景推荐模式关键特性
--------------------------
环环相扣的阶段顺序流水线dependsOn 依赖链
多角度思考问题Fan-Out/AggregateAgentPool.runParallel
开放性复杂任务团队协作sharedMemory + 分工
不可靠外部依赖重试机制maxRetries + 退避
生产环境运维全链路追踪onTrace + 成本分析

本章小结

  1. 团队协作模式：三 Agent 流水线（设计→实现→审查），适合工程类任务。
  1. MapReduce 模式：Fan-Out 并行分析多角度 → Aggregate 综合结论，适合决策类任务。
  1. 重试流水线：配置 maxRetries/retryDelayMs/retryBackoff，适合有外部依赖的任务。
  1. 全链路追踪：组合 onTrace/onProgress，适合生产环境运维和成本控制。

思考题

  1. 如果你需要增加一个"测试工程师"Agent 到案例一的流水线中，它应该放在哪个位置？依赖关系应该怎么设置？
  1. Fan-Out/Aggregate 模式中，如果三个分析师的结果互相矛盾，综合分析师应该如何处理？
  1. 案例四的成本估算使用了固定定价。实际生产中，如何处理多模型混合使用的情况？
