第 1 章：认识多智能体系统

从一个故事开始

想象你是一家软件公司的项目经理。今天早上，老板把你叫到办公室，说："我们需要一个用户登录系统，下班前给我。"

如果是传统方式，你会：

  1. 坐下来，花 1 小时写详细的任务分解文档
  2. 分配给张三做数据库设计，李四做后端接口，王五做前端页面
  3. 追着每个人问进度，处理各种依赖关系和阻塞问题
  4. 最后把所有人的成果拼在一起

但如果你是老板呢？你会怎么做？

你会说："小王啊，我需要一个用户登录系统。"然后继续喝你的咖啡。

Open Multi-Agent 就是这样一个"AI 项目经理"。 你只需要告诉它要什么，它会自动分解任务、分配给合适的 AI 员工、监督进度、处理问题，最后把完整的代码交到你手上。

这就是本章要介绍的核心框架：Open Multi-Agent——一个 TypeScript 原生的多智能体编排框架。

1.1 什么是多智能体系统？

在深入框架之前，我们先理解一个概念：多智能体系统（Multi-Agent System）。

💡 多智能体系统

顾名思义，就是多个 AI Agent（智能体）协同工作的系统。每个 Agent 就像一个专业的员工，有自己的角色定位、擅长的技能、能使用的工作工具。他们组合在一起，形成一个团队，共同完成复杂任务。

你可能会问：为什么不只用一个 Agent？

答案是：分工产生效率，专业产生质量。

就像一个建筑团队不会让电工去刷墙、让水管工去铺电线，多智能体系统让每个 Agent 专注于自己擅长的领域：

  • 研究员 Agent 负责搜集资料、分析需求
  • 开发者 Agent 负责写代码、实现功能
  • 审核员 Agent 负责检查代码质量、发现潜在问题

当他们协作时，整体产出质量远超单个 Agent 独自工作的结果。

1.2 为什么需要 Agent 编排框架？

有了多个 Agent，自然需要一套"管理办法"。

想象没有框架的情况：你要自己管理 Agent 的生命周期、任务分配、依赖关系、结果汇总、错误处理……光是想想就头疼。

Agent 编排框架（Orchestration Framework） 就是来解决这个问题的。它提供：

能力说明
------------
任务分解把大目标拆成小任务
智能调度根据依赖关系和资源情况安排执行顺序
结果汇总把多个 Agent 的输出整合成最终结果
错误处理单个任务失败不影响整体流程

1.3 Open Multi-Agent 的设计哲学

Open Multi-Agent 框架有三大核心理念：

1.3.1 Goal In, Result Out（目标进，结果出）

这是框架的设计初心。

// 只需要描述你的目标
const result = await orchestrator.runTeam(team, '创建一个 REST API 用户登录系统')

// 框架自动完成：目标分解 → 任务分配 → 并行执行 → 结果汇总
console.log(result.success)  // true
console.log(result.output)  // 完整的登录系统代码

不需要手动定义任务图，不需要指定谁先做谁后做，不需要处理复杂的依赖关系。你只管说要什么，框架负责怎么做。

1.3.2 Coordinator Pattern（协调者模式）

框架的秘密武器是自动协调者（Coordinator）。

当你调用 runTeam() 时，框架会：

  1. 启动一个临时的协调者 Agent（不是你自己创建的 Agent）
  2. 协调者阅读你的目标描述，理解你想要什么
  3. 协调者把大目标分解成具体任务，形成任务依赖图
  4. 协调者分配任务给团队成员，并根据依赖关系调度执行
  5. 协调者收集所有结果，整合成最终输出
graph LR A["Goal: 登录系统"] --> B["Coordinator"] B --> C["Task: 数据库设计"] B --> D["Task: 后端接口"] B --> E["Task: 前端页面"] C --> F["完成"] D --> F E --> F

这个协调者是框架的杀手级特性（Killer Feature）——它让"说需求"成为可能，而不需要"写代码"。

1.3.3 Parallel-by-Default（默认并行）

独立的任务会自动并行执行。

任务A（无依赖） ──┐
                  ├──► 并行执行，速度提升 3 倍
任务B（无依赖） ──┤
                  │
任务C（无依赖） ──┘

如果任务 B 依赖任务 A，那么 B 会等待 A 完成后才启动。框架自动处理这一切，你不需要操心。

1.3.4 Graceful Failure（优雅失败）

单个任务失败了怎么办？

框架的设计是：失败的任务标记自己为 failed，它的直接依赖者永久等待，其他任务继续执行。

任务A ──► 任务B（失败） ──► 任务C（永久等待 B）
任务A ──► 任务D（继续执行） ✓
任务A ──► 任务E（继续执行） ✓

这叫做"优雅失败"——局部失败不会导致全局崩溃，最大化你的有效输出。

1.4 框架的独特优势

TypeScript 原生

Open Multi-Agent 是用 TypeScript 编写的，专为 TypeScript 开发者设计。

  • 完整的类型提示：IDE 自动补全，告别猜测
  • Zod 集成：结构化输出 + 运行时验证，双重保障
  • 3 个运行时依赖：只有 @anthropic-ai/sdk、openai、zod，轻量如羽

模型无关

不绑定特定 LLM 提供商：

  • Anthropic: Claude 系列
  • OpenAI: GPT 系列
  • Google: Gemini
  • GitHub: Copilot
  • 本地模型: Ollama、vLLM、LM Studio

你可以在同一个团队里混用不同的模型，每个 Agent 可以选择最适合自己的。

轻量且可审计

3 个运行时依赖
33 个源码文件
可读性极高 —— 一个下午就能通读全框架

不像某些"重量级选手"，这个框架你可以完全读懂、完全掌控。

1.7 环境准备

在开始下一章之前，请确保你的环境满足要求：

  • Node.js >= 18：框架运行在 Node.js 之上
  • 包管理器：npm、pnpm 或 yarn 均可
  • API Key：至少准备一个 LLM 提供商的 API Key
# 检查 Node.js 版本
node --version  # 应该 >= 18.0.0

# 如果使用 Claude，还需要
echo $ANTHROPIC_API_KEY  # 应该有一串密钥

  1. 多智能体系统是多个 AI Agent 协同工作的架构，分工提升效率，专业保证质量。
  1. Open Multi-Agent 是一个 TypeScript 原生的 Agent 编排框架，核心理念是"Goal In, Result Out"。
  1. Coordinator Pattern 是框架的杀手级特性——自动把目标分解成任务图，无需手动定义。
