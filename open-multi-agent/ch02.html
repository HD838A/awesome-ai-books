第 2 章：快速上手

从"Hello World"到真实项目

上一章我们了解了 Open Multi-Agent 的设计理念。现在，让我们真正用它做点事情。

本章的目标很简单：用 5 分钟，运行你的第一个多 Agent 协作任务。

2.1 环境准备

2.1.1 安装 Node.js

框架运行在 Node.js 之上。确保你的环境满足要求：

# 检查 Node.js 版本（需要 >= 18）
node --version
# v20.x.x 或更高版本都 OK

# 如果显示 command not found 或版本 < 18
# 请访问 https://nodejs.org 下载安装

2.1.2 创建项目

# 创建新项目
mkdir my-agent-project
cd my-agent-project
npm init -y

# 安装框架
npm install @jackchen_me/open-multi-agent

# 安装 TypeScript 和运行工具（可选但推荐）
npm install -D typescript @types/node tsx
npx tsc --init

2.1.3 设置 API Key

框架需要调用 LLM API，需要设置认证密钥：

# 方式 1：环境变量（推荐）
export ANTHROPIC_API_KEY=sk-ant-xxxxx

# 方式 2：.env 文件 + dotenv（后续章节介绍）

⚠️ API Key 安全提醒

不要把 API Key 提交到代码仓库！生产环境建议使用 .env 文件管理。

2.1.4 创建入口文件

// src/index.ts
import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
})

console.log('环境检查通过！')

运行测试：

npx tsx src/index.ts
# 输出: 环境检查通过！

如果看到输出，恭喜你！环境已经准备好了。

2.2 第一个示例：单个 Agent

让我们从最简单的场景开始：让一个 Agent 帮你写代码。

2.2.1 代码

// src/01-hello-agent.ts
import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
})

async function main() {
  console.log('启动 Agent...\n')

  const result = await orchestrator.runAgent(
    {
      name: 'coder',
      model: 'claude-sonnet-4-6',
      systemPrompt: `You are a TypeScript developer.
Write clean, minimal code with no extra commentary.
Use the bash tool to run commands and file tools to read/write files.`,
      tools: ['bash', 'file_write'],
      maxTurns: 8,
    },
    `Create a TypeScript file /tmp/demo.ts that:
  1. Exports a function named greet(name: string): string
  2. Returns "Hello, <name>!"
  3. Include a usage example at the bottom
  Then run the file with: npx tsx /tmp/demo.ts`,
  )

  if (result.success) {
    console.log('\n✅ Agent 任务完成！')
    console.log('\n输出内容:')
    console.log('─'.repeat(50))
    console.log(result.output)
    console.log('─'.repeat(50))
    console.log(`\n📊 Token 消耗: 输入 ${result.tokenUsage.input_tokens}, 输出 ${result.tokenUsage.output_tokens}`)
    console.log(`🔧 工具调用次数: ${result.toolCalls.length}`)
  } else {
    console.error('❌ Agent 任务失败:', result.output)
  }
}

main()

2.2.4 代码解读

让我们拆解这段代码：

部分说明
------------
OpenMultiAgent框架的入口类，负责管理所有 Agent 和团队
defaultModel默认使用的 LLM 模型，这里是 Claude
runAgent()运行单个 Agent 的方法
AgentConfigAgent 的配置对象，定义它的角色和工具
systemPrompt给 Agent 的"指令"，定义它的角色和行为
toolsAgent 可以使用的工具，这里允许它执行命令和写文件
result.success任务是否成功完成

2.3 第二个示例：多 Agent 团队

单个 Agent 能做很多事，但真正的威力在于多个 Agent 协作。

2.3.1 场景

我们让一个团队来完成一个真实任务：

  • 架构师（Architect）：设计 API 结构
  • 开发者（Developer）：根据设计写代码
  • 审核员（Reviewer）：检查代码质量

2.3.2 代码

// src/02-team-demo.ts
import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'
import type { AgentConfig, OrchestratorEvent } from '@jackchen_me/open-multi-agent'

// 定义架构师 Agent
const architect: AgentConfig = {
  name: 'architect',
  model: 'claude-sonnet-4-6',
  systemPrompt: `You are a software architect.
Design clear, production-quality API contracts.
Output concise plans in markdown — no prose.`,
  tools: ['bash', 'file_write'],
  maxTurns: 5,
  temperature: 0.2,
}

// 定义开发者 Agent
const developer: AgentConfig = {
  name: 'developer',
  model: 'claude-sonnet-4-6',
  systemPrompt: `You are a TypeScript developer.
Write clean, runnable code with proper error handling.
Use the tools to write files and run tests.`,
  tools: ['bash', 'file_read', 'file_write', 'file_edit'],
  maxTurns: 12,
  temperature: 0.1,
}

// 定义审核员 Agent
const reviewer: AgentConfig = {
  name: 'reviewer',
  model: 'claude-sonnet-4-6',
  systemPrompt: `You are a senior code reviewer.
Review code for correctness, security, and clarity.
Provide a structured review with LGTM, suggestions, and blocking issues.`,
  tools: ['bash', 'file_read', 'grep'],
  maxTurns: 5,
  temperature: 0.3,
}

// 进度追踪函数
function handleProgress(event: OrchestratorEvent): void {
  const ts = new Date().toISOString().slice(11, 23)

  switch (event.type) {
    case 'agent_start':
      console.log(`[${ts}] 🤖 开始 → ${event.agent}`)
      break
    case 'agent_complete':
      console.log(`[${ts}] ✅ 完成 ← ${event.agent}`)
      break
    case 'task_start':
      console.log(`[${ts}] 📋 任务 ↓ ${event.task}`)
      break
    case 'task_complete':
      console.log(`[${ts}] 📋 完成 ↑ ${event.task}`)
      break
    case 'error':
      console.error(`[${ts}] ❌ 错误: ${event.agent}`)
  }
}

// 主函数
async function main() {
  const orchestrator = new OpenMultiAgent({
    defaultModel: 'claude-sonnet-4-6',
    onProgress: handleProgress,
  })

  // 创建团队
  const team = orchestrator.createTeam('api-team', {
    name: 'api-team',
    agents: [architect, developer, reviewer],
    sharedMemory: true,
  })

  console.log(`团队 "${team.name}" 已创建，成员: architect, developer, reviewer\n`)

  // 描述你的目标 —— 框架会自动分解任务
  const goal = `Create a REST API in /tmp/api/ with:
- GET /health → returns { status: "ok" }
- GET /users → returns hardcoded user list
- POST /users → accepts { name, email }, returns 201
- Include package.json with express dependency`

  console.log('开始执行...\n')
  console.log('='.repeat(50))

  const result = await orchestrator.runTeam(team, goal)

  console.log('='.repeat(50))
  console.log(`\n🎯 执行完成！成功率: ${result.success}`)

  // 查看每个 Agent 的结果
  console.log('\n📊 各 Agent 结果:')
  for (const [name, agentResult] of result.agentResults) {
    const status = agentResult.success ? '✅' : '❌'
    console.log(`  ${status} ${name}: 工具调用 ${agentResult.toolCalls.length} 次`)
  }
}

main()

2.3.5 发生了什么？

当你运行 runTeam() 时，背后发生的事情：

sequenceDiagram participant User as 你 participant Coord as Coordinator participant Team as 团队 Agent User->>Coord: runTeam("创建 REST API") Coord->>Coord: 分析目标 Coord->>Team: 分解任务：设计 → 开发 → 审核 Team->>Coord: 任务1完成 Team->>Coord: 任务2完成（并行） Team->>Coord: 任务3完成 Coord->>User: 返回最终结果

2.4 理解核心 API

2.4.1 OpenMultiAgent 类

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',  // 默认模型
  maxConcurrency: 5,                     // 最大并发数
  onProgress: (event) => {},            // 进度回调
  onTrace: (trace) => {},               // 追踪回调
})
配置项说明默认值
----------------------
defaultModel默认使用的 LLM 模型'claude-opus-4-6'
maxConcurrency同时运行的 Agent 数量5
onProgress任务状态变化回调无
onTrace详细追踪数据回调无

2.4.2 AgentConfig 对象

const agent: AgentConfig = {
  name: 'my-agent',        // 唯一标识符
  model: 'claude-sonnet-4-6',
  provider: 'anthropic',   // 可选，默认从 model 推断
  systemPrompt: '...',     // 角色定义（重要！）
  tools: ['bash', 'file_write'],  // 可用工具
  maxTurns: 10,            // 最大对话轮次
  temperature: 0.3,        // 输出随机性
}

💡 systemPrompt 技巧

systemPrompt 决定了 Agent 的"性格"。仔细设计它，就像写职位描述一样重要。

2.4.3 TeamRunResult 结果对象

const result = await orchestrator.runTeam(team, goal)

// result 结构：
{
  success: true,                    // 是否整体成功

2.5 常见问题

Q1: 报错 ANTHROPIC_API_KEY is not set

你没有设置 API Key。在终端运行：

export ANTHROPIC_API_KEY=sk-ant-xxxxx

Q2: 报错 Model not found

模型名称不对。常用模型：

  • 'claude-opus-4-6' — 最强 Claude
  • 'claude-sonnet-4-6' — 平衡型（推荐，速度快）
  • 'claude-haiku-3-5' — 最快 Claude

Q3: Agent 不按预期工作

检查 systemPrompt 是否清晰。像给新员工写入职指南一样写它。

Q4: 任务超时

增加 maxTurns 或检查 systemPrompt 是否过于复杂。

本章小结

  1. 环境准备只需 Node.js >= 18 和一个 API Key。
  1. runAgent() 是最简单的入口，适合单一任务。
  1. runTeam() 开启多 Agent 协作，只需描述目标，框架自动分解任务。
  1. AgentConfig 定义 Agent 的角色、工具和行为，systemPrompt 是关键。
  1. onProgress 回调让你实时了解执行进度。

思考题

  1. 如果让三个 Agent 并行工作（去掉依赖），效率会提升多少？有什么风险？
  1. systemPrompt 中，架构师用 temperature: 0.2，审核员用 0.3。为什么不同角色用不同的温度？
  1. 你能想到哪些 runTeam() 的实际应用场景？
