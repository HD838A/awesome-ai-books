第 6 章：多模型支持

一个团队，多种能力

在现实中，一个高效的团队会招募不同专长的成员：

  • 架构师负责系统设计
  • 开发者负责编码实现
  • 测试工程师负责质量保障

同样，在 Open Multi-Agent 中，你可以让不同的 Agent 使用不同的 AI 模型，发挥各自的优势。本章我们将学习如何：

  • 配置不同的 LLM 提供商
  • 在同一团队中混合使用多种模型
  • 连接本地模型（如 Ollama）

6.1 LLM 适配器架构

6.1.1 为什么需要适配器？

每个 LLM 提供商的 API 都不一样：

Anthropic:  messages.create({ model: 'claude-3-5-sonnet-20241022', ... })
OpenAI:     chat.completions.create({ model: 'gpt-4o', ... })
Gemini:     model.generateContent({ model: 'gemini-2.0-flash', ... })

如果框架直接调用这些 API，代码会变得混乱不堪。

解决方案：适配器模式（Adapter Pattern）

┌─────────────────────────────────────────────────────────────┐
│                      框架代码                                │
│                                                              │
│  agent.chat(messages)  ←── 统一的 LLMAdapter 接口           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
                          │
           ┌──────────────┼──────────────┐
           ▼              ▼              ▼
      ┌─────────┐   ┌──────────┐   ┌────────┐
      │Anthropic│   │  OpenAI  │   │ Gemini │
      │Adapter  │   │ Adapter  │   │Adapter │
      │  ↓ API  │   │   ↓ API  │   │  ↓ API │
      └─────────┘   └──────────┘   └────────┘

6.1.2 LLMAdapter 接口

所有适配器都实现统一的接口：

interface LLMAdapter {
  // 发送消息，获取回复
  chat(messages: LLMMessage[], options: LLMChatOptions): Promise<LLMResponse>

  // 流式输出（逐字返回）
  stream(messages: LLMMessage[], options: LLMStreamOptions): AsyncGenerator<StreamEvent>

  // 获取模型能力（如是否支持工具调用）
  getCapabilities(): LLMAdapterCapabilities

  // 估算 token 数量
  getTokenEstimate(text: string): number
}

6.2 创建适配器

6.2.1 使用 createAdapter 工厂

import { createAdapter } from '@jackchen_me/open-multi-agent'

// 创建 Anthropic 适配器（使用 Claude）
const anthropicAdapter = await createAdapter('anthropic')

// 创建 OpenAI 适配器（使用 GPT-4）
const openaiAdapter = await createAdapter('openai')

// 创建 Gemini 适配器
const geminiAdapter = await createAdapter('gemini')

6.2.2 API Key 配置

方式 1：环境变量（推荐）

# .env 文件
ANTHROPIC_API_KEY=sk-ant-xxxxx
OPENAI_API_KEY=sk-proj-xxxxx
GEMINI_API_KEY=xxxxx

方式 2：构造函数参数（覆盖环境变量）

const adapter = await createAdapter(
  'anthropic',
  'sk-ant-xxxxx'  // 显式传入 API Key
)

6.2.3 API Key 回退机制

框架按以下优先级查找 API Key：

构造函数参数 > 环境变量 > SDK 默认值

// 伪代码实现
class AnthropicAdapter {
  constructor(privateApiKey?: string) {
    this.apiKey = privateApiKey ?? process.env.ANTHROPIC_API_KEY
  }
}

6.4 多模型团队

6.4.1 为什么混合使用模型？

不同的模型有不同的优势：

架构师 (Claude Sonnet)     → 强大的分析和推理能力
开发者 (GPT-4o)           → 优秀的代码生成
审核员 (Claude Opus)      → 细致的审查能力

6.4.2 创建多模型团队

import { OpenMultiAgent } from '@jackchen_me/open-multi-agent'

const orchestrator = new OpenMultiAgent({
  defaultModel: 'claude-sonnet-4-6',
})

// 架构师：使用 Claude Sonnet
const architect: AgentConfig = {
  name: 'architect',
  provider: 'anthropic',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个经验丰富的软件架构师。
你擅长设计可扩展、高性能的分布式系统。
你会考虑系统的长期可维护性。`,
  tools: ['bash', 'file_write'],
}

// 开发者：使用 GPT-4o
const developer: AgentConfig = {
  name: 'developer',
  provider: 'openai',
  model: 'gpt-4o',
  systemPrompt: `你是一个全栈开发工程师。
你擅长编写简洁、可维护的代码。
你会遵循最佳实践和代码规范。`,
  tools: ['bash', 'file_read', 'file_write', 'file_edit'],
}

// 审核员：使用 Claude Opus（最强模型）
const reviewer: AgentConfig = {
  name: 'reviewer',
  provider: 'anthropic',
  model: 'claude-opus-4-6',
  systemPrompt: `你是一个资深代码审查专家。
你关注代码的正确性、安全性和性能。
你会提出建设性的改进建议。`,
  tools: ['bash', 'grep', 'file_read'],
}

// 创建团队
const team = orchestrator.createTeam('dev-team', {
  name: 'dev-team',
  agents: [architect, developer, reviewer],
  sharedMemory: true,
})

6.4.3 多模型协作示例

async function buildProject(goal: string) {
  const result = await orchestrator.runTeam(team, goal)

  console.log('各 Agent 结果:')
  for (const [name, agentResult] of result.agentResults) {
    const model = team.getAgents().find(a => a.name === name)?.model
    console.log(`  ${name} (${model}): ${agentResult.success ? '✅' : '❌'}`)
  }
}

// 运行
await buildProject('创建一个电商网站后端 API')

6.5 本地模型支持

6.5.1 为什么使用本地模型？

  • 隐私：数据不离开你的机器
  • 成本：免费使用，无需 API Key
  • 速度：本地运行，无网络延迟

6.5.2 使用 Ollama

1. 安装 Ollama

# macOS
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh

2. 下载模型

ollama pull llama3.2
ollama pull codellama

3. 配置框架

// Ollama 提供 OpenAI 兼容 API
const adapter = await createAdapter(
  'openai',                        // 使用 OpenAI 适配器
  'ollama-is-local',              // Ollama 不需要真正的 API Key
  'http://localhost:11434/v1'      // Ollama 的 base URL
)

// 或者在 Agent 中配置
const localAgent: AgentConfig = {
  name: 'local-assistant',
  provider: 'openai',
  model: 'llama3.2',              // Ollama 模型名
  apiKey: 'ollama-is-local',      // 占位符
  baseURL: 'http://localhost:11434/v1',
}

6.5.3 使用 vLLM

// vLLM 服务器
const adapter = await createAdapter(
  'openai',
  'my-api-key',                    // vLLM 服务的 API Key
  'https://vllm.example.com/v1'   // vLLM base URL
)

6.6 模型选择指南

6.6.1 根据任务类型选择

任务类型推荐模型理由
--------------------------
系统架构设计Claude Opus/Sonnet强大的分析和推理能力
代码生成GPT-4o / Claude Sonnet优秀的长上下文理解
代码审查Claude Opus细致入微的分析
简单任务GPT-3.5 / Claude Haiku成本低，速度快
图像理解GPT-4o / Claude多模态支持

6.6.2 成本优化策略

// 策略 1：简单任务用便宜模型
const simpleAgent: AgentConfig = {
  name: 'formatter',
  provider: 'anthropic',
  model: 'claude-haiku-3-5',  // 便宜快速
  systemPrompt: '你格式化代码，确保符合规范。',
}

// 策略 2：复杂任务用强大模型
const complexAgent: AgentConfig = {
  name: 'architect',
  provider: 'anthropic',
  model: 'claude-opus-4-6',   // 昂贵但强大
  systemPrompt: '你设计系统架构。',
}

6.6.3 模型比较示例

// 测试不同模型对同一问题的回答
const question = '解释什么是依赖注入，以及它的好处'

const models = ['claude-sonnet-4-6', 'gpt-4o', 'gemini-2.0-flash']

for (const model of models) {
  const adapter = await createAdapter('anthropic', undefined, undefined)
  const result = await adapter.chat(
    [{ role: 'user', content: [{ type: 'text', text: question }] }],
    { model, maxTokens: 500 }
  )
  console.log(`\n=== ${model} ===\n${result.message.content[0]?.text}`)
}

6.7 常见问题

Q1: 报错 Model not found

确保模型名称正确：

// Anthropic 模型名
'claude-opus-4-6'      // ✓
'claude-sonnet-4-6'    // ✓
'claude-3-5-sonnet'    // ✗ 旧格式

// OpenAI 模型名
'gpt-4o'               // ✓
'gpt-4-turbo'          // ✓
'chatgpt-4'            // ✗

Q2: 报错 Invalid API Key

检查环境变量：

# 验证环境变量
echo $ANTHROPIC_API_KEY   # 应该有值
echo $OPENAI_API_KEY      # 应该有值

Q3: Ollama 连接失败

确保 Ollama 服务正在运行：

# 启动 Ollama 服务
ollama serve

# 测试连接
curl http://localhost:11434/api/tags

本章小结

  1. 适配器模式：统一接口，隐藏不同 LLM 提供商的差异。
  1. createAdapter 工厂：一行代码创建适配器，支持懒加载。
  1. 五大提供商：Anthropic、OpenAI、Gemini、Grok、Copilot。
  1. 多模型团队：每个 Agent 可以使用不同模型，发挥各自优势。
  1. 本地模型：通过 OpenAI 兼容 API 支持 Ollama 和 vLLM。
  1. 成本优化：简单任务用便宜模型，复杂任务用强大模型。

思考题

  1. 如果你要构建一个"代码审查助手"，你会选择哪些 Agent？它们分别用什么模型？
  1. Ollama 使用 OpenAI 兼容 API，但不需要真正的 API Key。框架是如何处理这种情况的？
  1. 在多模型团队中，不同模型的 Token 计费是独立的。如何估算整个团队的总成本？
