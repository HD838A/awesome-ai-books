第 7 章：共享内存与通信

Agent 之间的"记忆共享"

想象一个真实的软件团队：

  • 架构师在白板上画了系统设计图
  • 开发者看到设计后开始写代码
  • 测试工程师基于开发者的代码写测试用例

他们之间需要共享信息。架构师不会每次都重新解释设计，开发者也不会每次都问架构师"系统要做什么"。

在 Open Multi-Agent 中，SharedMemory（共享内存） 就是团队成员之间的"白板"——让 Agent 能够共享信息，而不需要每次都重新传递上下文。

7.1 SharedMemory 概述

7.1.1 核心概念

SharedMemory 是一个命名空间隔离的键值存储：

import { SharedMemory } from '@jackchen_me/open-multi-agent'

const memory = new SharedMemory()

写入数据：

// Agent "researcher" 在自己的区域写入
await memory.write('researcher', 'findings', 'TypeScript 5.5 支持 const 类型参数')

// Agent "developer" 在自己的区域写入
await memory.write('developer', 'plan', '使用 const 类型参数重构泛型')

读取数据：

// 按完整 key 读取
const entry = await memory.read('researcher/findings')
console.log(entry?.value)  // "TypeScript 5.5 支持 const 类型参数"

// 按 Agent 过滤
const researcherEntries = await memory.listByAgent('researcher')
console.log(researcherEntries)
// [{ key: 'researcher/findings', value: '...', metadata: { agent: 'researcher' } }]

7.1.2 命名空间设计

为什么用 agentName/key 作为 key？

┌─────────────────────────────────────────────────────────────┐
│                    SharedMemory                              │
│                                                              │
│  researcher/findings ────────────────────────────────────┐   │
│  researcher/api-design ───────────────────────────────┐  │   │
│  developer/plan ──────────────────────────────────┐   │  │   │
│  developer/test-status ───────────────────────┐   │  │  │   │
│  reviewer/comments ───────────────────────┐    │   │  │  │   │
│                                           │    │   │  │  │   │
└───────────────────────────────────────────┴────┴───┴──┴───┘   │
                                               │    │   │  │
                                              ┌┘    │   │  │
                                              │researcher│  │
                                              │         │  │
                                              │developer │  │
                                              │          │
                                              │reviewer  │
                                              └──────────┘

好处：

  • 不同 Agent 的数据不会冲突
  • 便于按 Agent 过滤
  • 数据来源可追溯（metadata.agent）

7.2 团队共享内存

7.2.1 创建团队时启用

const team = orchestrator.createTeam('dev-team', {
  name: 'dev-team',
  agents: [architect, developer, reviewer],
  sharedMemory: true,  // 启用共享内存
})

// 获取团队的共享内存实例
const memory = team.getSharedMemory()

7.2.2 Agent 内部使用

在自定义工具中访问共享内存：

const fileWriteTool = defineTool({
  name: 'file_write',
  description: 'Write content to a file and record the action in team memory.',

  inputSchema: z.object({
    path: z.string(),
    content: z.string(),
    record?: z.boolean().default(true),  // 是否记录到共享内存
  }),

  execute: async ({ path, content, record = true }) => {
    await fs.writeFile(path, content)

    if (record) {
      const memory = team.getSharedMemory()
      await memory.write('developer', 'files_written', `Created ${path}`)
    }

    return { data: `Written to ${path}`, isError: false }
  },
})

7.2.3 跨 Agent 数据传递

// Agent A：研究阶段，写入发现
await memory.write('researcher', 'competitors', JSON.stringify({
  productA: { price: 100, features: ['a', 'b'] },
  productB: { price: 80, features: ['b', 'c'] },
}))

// Agent B：分析阶段，读取研究结果
const research = await memory.read('researcher/competitors')
const competitors = JSON.parse(research?.value ?? '{}')

// Agent C：撰写报告，引用分析结论
const report = `基于竞品分析，${competitors.productA.name} 的定价偏高...`

7.3.2 注入到 System Prompt

// 在 Agent 配置中使用摘要
const analyst: AgentConfig = {
  name: 'analyst',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个数据分析师。

以下是团队共享的信息：
${await memory.getSummary()}

请基于以上信息进行数据分析。`,
}

7.3.3 动态更新上下文

每次 Agent 运行时获取最新摘要：

async function runWithMemory(agent: Agent, prompt: string, memory: SharedMemory) {
  const summary = await memory.getSummary()
  const contextPrompt = summary
    ? `${prompt}\n\n## Team Context\n${summary}`
    : prompt

  return await agent.run(contextPrompt)
}

7.4 MemoryStore 接口

SharedMemory 基于 MemoryStore 接口实现：

interface MemoryStore {
  get(key: string): Promise<MemoryEntry | null>
  set(key: string, value: string, metadata?: Record<string, unknown>): Promise<void>
  list(): Promise<MemoryEntry[]>
}

interface MemoryEntry {
  key: string
  value: string
  metadata: Record<string, unknown>
  createdAt: Date
  updatedAt: Date
}

7.4.1 内置实现：InMemoryStore

默认使用内存存储：

import { InMemoryStore } from '@jackchen_me/open-multi-agent'

const store = new InMemoryStore()
await store.set('key', 'value')
const entry = await store.get('key')

7.4.2 自定义存储后端

实现 MemoryStore 接口，使用 Redis、PostgreSQL 等持久化存储：

import type { MemoryStore } from '@jackchen_me/open-multi-agent'

class RedisStore implements MemoryStore {
  constructor(private client: Redis) {}

  async get(key: string) {
    const data = await this.client.hgetall(key)
    if (!data) return null
    return {
      key,
      value: data.value,
      metadata: JSON.parse(data.metadata ?? '{}'),
      createdAt: new Date(data.createdAt),
      updatedAt: new Date(data.updatedAt),
    }
  }

  async set(key: string, value: string, metadata?: Record<string, unknown>) {
    await this.client.hmset(key, { value, metadata: JSON.stringify(metadata) })
  }

  async list() {
    const keys = await this.client.keys('*')
    return Promise.all(keys.map(k => this.get(k)))
  }
}

// 使用自定义存储
const redisStore = new RedisStore(redisClient)
const memory = new SharedMemory(redisStore)

7.5 团队通信机制

7.5.1 事件总线

Team 内部包含 EventBus，用于 Agent 间事件通知：

// 监听团队事件
team.on('agent:start', (event) => {
  console.log(`Agent "${event.agent}" 开始执行`)
})

team.on('agent:complete', (event) => {
  console.log(`Agent "${event.agent}" 完成`)
})

team.on('task:complete', (event) => {
  console.log(`任务 "${event.task}" 完成`)
})

7.5.2 共享内存作为通信媒介

// Agent A 通知 Agent B
await memory.write('agent-a', 'status', '已完成初步分析')
await memory.write('agent-a', 'result', JSON.stringify(analysisResult))

// Agent B 检查 Agent A 的状态
const aStatus = await memory.read('agent-a/status')
if (aStatus?.value === '已完成初步分析') {
  const aResult = JSON.parse((await memory.read('agent-a/result'))?.value)
  // 使用 Agent A 的结果
}

7.5.3 共享工具注册表

团队中的所有 Agent 共享同一个 ToolRegistry：

const registry = new ToolRegistry()
registry.register(customTool)

// 所有 Agent 都可以使用这个工具
team.getAgents().forEach(agent => {
  console.log(agent.name, '可用的工具:', registry.list().map(t => t.name))
})

7.6 实践案例：研究→分析→报告流水线

async function researchPipeline(query: string) {
  const memory = new SharedMemory()
  const orchestrator = new OpenMultiAgent()

  // 研究员：搜索和整理信息
  const researcher = orchestrator.createAgent({
    name: 'researcher',
    systemPrompt: `你是一个研究员，负责收集信息。
将重要发现记录到共享内存：await memory.write('researcher', 'findings', ...)`,
    tools: ['web_search', 'bash'],
  })

  // 分析员：分析收集的信息
  const analyst = orchestrator.createAgent({
    name: 'analyst',
    systemPrompt: `你是一个分析师。
读取研究员的发现：memory.read('researcher/findings')
将分析结果记录到共享内存：memory.write('analyst', 'insights', ...)`,
    tools: ['bash'],
  })

  // 报告员：撰写最终报告
  const writer = orchestrator.createAgent({
    name: 'writer',
    systemPrompt: `你是一个技术作家。
读取所有发现和分析：memory.listAll()
撰写最终报告。`,
    tools: ['file_write'],
  })

  // 阶段 1：研究
  await researcher.run(`研究 ${query}，记录关键发现`)

  // 阶段 2：分析
  const findings = await memory.read('researcher/findings')
  await analyst.run(`分析以下发现：${findings?.value}`)

  // 阶段 3：写作
  const insights = await memory.read('analyst/insights')
  await writer.run(`基于以下分析撰写报告：${insights?.value}`)

  // 输出完整上下文
  console.log(await memory.getSummary())
}

7.7 最佳实践

7.7.1 命名规范

// ✅ 推荐：清晰的层级命名
await memory.write('researcher', 'sources/2024-q1', '...')
await memory.write('researcher', 'findings/feature-x', '...')

// ❌ 不推荐：无结构的 key
await memory.write('researcher', 'stuff1', '...')
await memory.write('researcher', 'stuff2', '...')

7.7.2 数据大小控制

// 存储大对象前考虑压缩或摘要
const largeData = await fetchHugeDataset()

// 选项 1：只存摘要
await memory.write('analyst', 'dataset-summary', summarize(largeData))

// 选项 2：分块存储
for (const chunk of chunkArray(largeData, 1000)) {
  await memory.write('analyst', `dataset/chunk-${i}`, JSON.stringify(chunk))
}

7.7.3 过期数据清理

// 定期清理过期数据
async function cleanupMemory(memory: SharedMemory, maxAgeMs: number) {
  const all = await memory.listAll()
  const now = Date.now()

  for (const entry of all) {
    const age = now - entry.updatedAt.getTime()
    if (age > maxAgeMs) {
      await memory.getStore().delete(entry.key)  // 如果 store 支持 delete
    }
  }
}

本章小结

  1. SharedMemory 是团队 Agent 之间的共享存储，基于命名空间（agentName/key）实现隔离和可追溯性。
  1. write() 将数据写入特定 Agent 的命名空间，read() 按完整 key 读取，listByAgent() 按 Agent 过滤。
  1. getSummary() 生成 Markdown 格式的摘要，可以直接注入到 Agent 的 system prompt。
  1. MemoryStore 接口 支持自定义后端（Redis、PostgreSQL），只需实现 get/set/list。
  1. 团队通信：共享内存 + EventBus 构成完整的 Agent 间通信机制。
