第 8 章：结构化输出与重试

让 AI 输出更可靠

默认情况下，LLM 输出的是自由文本。这对于写作、聊天等场景很合适。但在编程场景中，我们需要：

  • 返回类型安全的 JSON 数据
  • 遇到临时错误时自动重试
  • 防止 Agent 进入死循环

本章我们将学习 Open Multi-Agent 如何解决这些问题。

8.1 结构化输出

8.1.1 问题

让 LLM 输出精确的 JSON 格式是很困难的：

// ❌ LLM 可能输出这样的"混乱"结果：
// "Here is the data: { \"name\": \"Alice\", \"age\": 30 }"
// 或者
// "```json\n{...}\n```"
// 甚至
// "根据您的要求，以下是结果：{name: 'Alice', age: 30}"

8.1.2 解决方案：三步曲

框架提供了完整的三步解决方案：

┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ 1. Prompt 注入   │    │ 2. JSON 提取     │    │ 3. Zod 验证     │
│                  │    │                  │    │                  │
│ 在 systemPrompt  │    │ 从可能混乱的     │    │ 用 Zod schema   │
│ 中告诉 LLM 输出  │ ──►│ 输出中找到      │ ──►│ 验证并转换     │
│ 什么格式         │    │ JSON 对象        │    │ 类型安全的结果  │
└──────────────────┘    └──────────────────┘    └──────────────────┘

8.1.3 第一步：定义 Schema

import { z } from 'zod'

const UserSchema = z.object({
  name: z.string().describe('用户名'),
  age: z.number().describe('年龄'),
  email: z.string().email().describe('邮箱地址'),
  role: z.enum(['admin', 'user', 'guest']).describe('用户角色'),
})

8.1.4 第二步：配置 Agent

import { buildStructuredOutputInstruction } from '@jackchen_me/open-multi-agent'

const userSchema = z.object({
  name: z.string(),
  age: z.number(),
  email: z.string().email(),
  role: z.enum(['admin', 'user', 'guest']),
})

const instruction = buildStructuredOutputInstruction(userSchema)
// instruction 输出：
// ## Output Format (REQUIRED)
// You MUST respond with ONLY valid JSON that conforms to...
// {"type": "object", "properties": {"name": {...}, ...}, ...}

const agent: AgentConfig = {
  name: 'data-extractor',
  model: 'claude-sonnet-4-6',
  systemPrompt: `你是一个数据提取专家。
从用户输入中提取信息并以 JSON 格式返回。
${instruction}`,
  tools: [],
  outputSchema: userSchema,  // 框架自动注入指令
}

8.1.5 第三步：使用结果

// 方式 1：直接从 result 获取
const result = await agent.run('用户 Alice，30岁，邮箱 alice@example.com')

if (result.outputSchemaResult) {
  const user = result.outputSchemaResult as z.infer<typeof UserSchema>
  console.log(user.name)    // "Alice"
  console.log(user.age)     // 30
  console.log(user.email)   // "alice@example.com"
}

// 方式 2：手动提取和验证
import { extractJSON, validateOutput } from '@jackchen_me/open-multi-agent'

const parsed = extractJSON(result.output)  // 提取 JSON
const user = validateOutput(UserSchema, parsed)  // 验证
console.log(user.name)  // "Alice"

8.2 AgentRunner 的对话循环

8.2.1 核心流程

AgentRunner 是框架的核心，它运行一个多轮对话循环：

flowchart TD A["开始"] --> B["发送消息到 LLM"] B --> C["接收 LLM 响应"] C --> D{"有工具调用?"} D -- 是 --> E["执行工具"] E --> F["将结果添加回对话"] F --> B D -- 否 --> G["结束，返回输出"]

8.2.2 流式事件

框架使用 AsyncGenerator 提供实时流式事件：

for await (const event of agent.stream('写一首关于 AI 的诗')) {
  switch (event.type) {
    case 'text':
      process.stdout.write(event.data)  // 实时显示
      break

    case 'tool_use':
      console.log(`\n🔧 调用工具: ${event.data.name}`)
      break

    case 'tool_result':
      console.log(`✅ 工具结果: ${event.data.content?.slice(0, 50)}...`)
      break

    case 'loop_detected':
      console.log(`⚠️ 检测到循环: ${event.data.detail}`)
      break

    case 'done':
      console.log('\n🎉 完成！')
      break

    case 'error':
      console.error(`❌ 错误: ${event.data.message}`)
      break
  }
}

8.2.3 回调选项

const result = await agent.run('生成报告', {
  onToolCall: (name, input) => {
    console.log(`🔧 ${name}(${JSON.stringify(input)})`)
  },
  onToolResult: (name, result) => {
    console.log(`✅ ${name}: ${result.isError ? '❌' : '✓'}`)
  },
  onMessage: (message) => {
    console.log(`📨 消息: ${message.role}`)
  },
  onWarning: (msg) => {
    console.warn(`⚠️ 警告: ${msg}`)
  },
})

8.3 循环检测

8.3.1 问题

有时 Agent 会陷入"死循环"：

Turn 1: 调用 bash("ls") → 失败
Turn 2: 调用 bash("ls") → 失败
Turn 3: 调用 bash("ls") → 失败
Turn 4: ...无限循环

8.3.2 LoopDetector

框架使用滑动窗口检测循环：

interface LoopDetectionConfig {
  maxRepetitions?: number      // 连续重复多少次触发（默认 3）
  loopDetectionWindow?: number  // 滑动窗口大小（默认 4）
  onLoopDetected?: 'warn' | 'terminate' | ((info) => 'continue' | 'inject' | 'terminate')
}

const agent: AgentConfig = {
  name: 'developer',
  model: 'claude-sonnet-4-6',
  loopDetection: {
    maxRepetitions: 3,
    onLoopDetected: 'terminate',  // 检测到循环直接终止
  },
}

8.3.3 处理策略

策略行为
------------
'warn'第一次警告，继续执行；如果再次检测到，终止
'terminate'直接终止对话
'continue'无视，继续执行
'inject'注入警告到上下文中，让 LLM 自我修正
// 自定义处理函数
const agent: AgentConfig = {
  name: 'developer',
  loopDetection: {
    maxRepetitions: 2,
    onLoopDetected: (info) => {
      console.error(`检测到循环: ${info.detail}`)
      return 'inject'  // 注入警告到上下文
    },
  },
}

8.3.4 检测内容

LoopDetector 检测两种循环：

  1. 工具调用重复：相同工具 + 相同参数反复调用
  2. 文本输出重复：相同的文本响应反复出现

8.4 重试机制

8.4.1 为什么需要重试？

LLM API 调用可能因为以下原因失败：

  • 网络临时不可用
  • API 限流（Rate Limit）
  • 服务端临时过载
  • 验证错误（可恢复）

这些错误通常是临时性的，重试往往能成功。

8.4.2 重试配置

const task = createTask({
  title: '调用外部 API',
  description: '调用天气 API 获取数据',
  maxRetries: 3,        // 最多重试 3 次（总尝试 4 次）
  retryDelayMs: 1000,   // 基础延迟 1 秒
  retryBackoff: 2,       // 退避系数：2 = 指数退避
})

8.4.3 指数退避

graph LR A["Attempt 1
失败"] --> B["等待 1s"] B --> C["Attempt 2
失败"] C --> D["等待 2s"] D --> E["Attempt 3
失败"] E --> F["等待 4s"] F --> G["Attempt 4
成功"]

延迟计算：

delay = min(baseDelay * backoff^(attempt-1), MAX_DELAY)
       = min(1000 * 2^(attempt-1), 60000)
       = min(1000, 60000) = 1s
       = min(2000, 60000) = 2s
       = min(4000, 60000) = 4s
       = ...

8.4.4 重试回调

const result = await orchestrator.runTasks(tasks, agents, {
  onRetry: ({ attempt, maxAttempts, error, nextDelayMs }) => {
    console.log(`重试 ${attempt}/${maxAttempts}: ${error}`)
    console.log(`下次延迟: ${nextDelayMs}ms`)
  },
})

8.4.5 重试 vs 不重试

// 适合重试的错误：
// - 网络超时
// - API Rate Limit (429)
// - 服务器临时错误 (503)

// 不适合重试的错误：
// - 认证失败 (401) — API Key 错误，重试也不会成功
// - 参数错误 (400) — 请求格式错误
// - 业务逻辑错误 — 数据本身的问题

8.5 综合示例

8.5.1 场景：结构化数据提取 + 重试

import { z } from 'zod'

const ArticleSchema = z.object({
  title: z.string().describe('文章标题'),
  author: z.string().describe('作者'),
  publishedAt: z.string().describe('发布日期 (ISO 8601)'),
  tags: z.array(z.string()).describe('标签列表'),
  summary: z.string().describe('文章摘要'),
  url: z.string().url().describe('文章链接'),
})

const ArticleExtractor: AgentConfig = {
  name: 'extractor',
  model: 'claude-sonnet-4-6',
  outputSchema: ArticleSchema,
  loopDetection: { maxRepetitions: 3, onLoopDetected: 'terminate' },
}

async function extractArticle(url: string): Promise<z.infer<typeof ArticleSchema>> {
  for (let attempt = 1; attempt <= 3; attempt++) {
    try {
      const result = await agent.run(`提取 ${url} 的文章信息`)
      return result.outputSchemaResult as z.infer<typeof ArticleSchema>
    } catch (error) {
      if (attempt === 3) throw error
      const delay = 1000 * Math.pow(2, attempt - 1)
      console.log(`第 ${attempt} 次尝试失败，${delay}ms 后重试...`)
      await sleep(delay)
    }
  }
  throw new Error('提取失败')
}

8.5.2 场景：循环检测 + 自动修正

const SafeDeveloper: AgentConfig = {
  name: 'developer',
  model: 'claude-sonnet-4-6',
  tools: ['bash', 'file_read', 'file_write', 'file_edit'],
  loopDetection: {
    maxRepetitions: 2,
    onLoopDetected: 'inject',  // 注入警告，让 LLM 自我修正
  },
  systemPrompt: `你是一个开发者，负责修复 bug。

重要规则：
1. 每次修复后必须运行测试验证
2. 如果测试持续失败，不要重复相同的操作
3. 尝试不同的方法解决问题`,
}

// 运行
for await (const event of developer.stream('修复 /tmp/app.ts 中的空指针错误')) {
  if (event.type === 'loop_detected') {
    console.log(`⚠️ 检测到可能的循环: ${event.data.detail}`)
    console.log('框架将注入警告到上下文中...')
  }
}

8.6 最佳实践

8.6.1 结构化输出

  1. 使用描述性字段名：Zod 的 .describe() 会成为 JSON Schema 的一部分
  2. 添加示例：在 systemPrompt 中提供输出示例
  3. 验证始终进行：即使 LLM 输出看起来正确，也要验证
const ProductSchema = z.object({
  name: z.string().describe('产品名称，例如 "iPhone 15 Pro"'),
  price: z.number().min(0).describe('价格（人民币）'),
  inStock: z.boolean().describe('是否有库存'),
})

8.6.2 循环检测

  1. 设置合理的阈值：maxRepetitions: 3 通常足够
  2. 使用 'inject' 策略：让 LLM 有机会自我修正
  3. 记录循环详情：用于调试和改进 Agent

8.6.3 重试策略

// 快速失败场景（如用户请求）
const task = createTask({ title: '快速操作', maxRetries: 0 })

// 可靠性优先场景（如数据提取）
const task = createTask({
  title: '可靠提取',
  maxRetries: 3,
  retryDelayMs: 1000,
  retryBackoff: 2,
})

// 指数退避 + 抖动（避免雷鸣羊群效应）
const jitter = Math.random() * 1000  // 0-1秒随机抖动
await sleep(delay + jitter)

本章小结

  1. 结构化输出三步曲：buildStructuredOutputInstruction → extractJSON → validateOutput
  1. AgentRunner 对话循环：LLM → 工具调用 → 结果回传 → 循环
  1. 流式事件：AsyncGenerator 提供 text/tool_use/tool_result/done/error/loop_detected
  1. 循环检测：滑动窗口检测相同工具调用或文本输出，可配置 warn/terminate/inject
  1. 重试机制：指数退避，maxRetries/retryDelayMs/retryBackoff 配置

思考题

  1. 如果 LLM 输出了 JSON 但不符合 Zod schema（多了字段），validateOutput 会怎么处理？
  1. 循环检测中，为什么用滑动窗口而不是记录所有历史？滑动窗口的大小应该如何选择？
  1. 指数退避的抖动（Jitter）为什么重要？它解决了什么问题？
