第10章：搭建你的 Scriptorium

本章目标
  • 理解 Scriptorium 的扩展性设计
  • 掌握添加新 Agent 的方法
  • 了解定制化写作流程的策略
  • 展望 Scriptorium 的未来发展方向

10.1 不是终点，而是起点

这本书的最后一章不是关于"用 Scriptorium 写书"，而是关于"搭建你自己的 Scriptorium"。

Scriptorium 不是一个封闭的产品，而是一个可扩展的框架。它的设计哲学是：

给你工具，但不限制你的想象力。

10.2 扩展性设计回顾

Scriptorium 的扩展性源于几个核心设计：

10.2.1 Agent 可插拔

新增一个 Agent 只需要：

  1. 创建 agents/XX-name.md 规范文件
  2. 在主编排的调度逻辑中注册
  3. 定义 File Pointers 输入输出

不需要修改核心引擎。

10.2.2 文件类型开放

Scriptorium 没有规定"只能写技术书"。只要你定义合适的：

  • style-guide.md
  • glossary.md
  • metaphor-registry.md

你可以用它来写：

  • 用户手册
  • 产品白皮书
  • 培训教材
  • 学术论文

10.2.3 Phase 可配置

五阶段流水线不是铁板一块。你可以：

原始设计可定制
Phase 1 固定 3 步可以添加/删除步骤
Phase 3 每批 3 章可以调整批次大小
Phase 4 固定 4 个 Agent可以增减审查 Agent
Phase 5 固定 2 个 Agent可以添加新的发布格式

10.3 添加新 Agent 的指南

假设你想添加一个新的 技术插画师 Agent（#13），负责为章节生成技术插图。

10.3.1 第一步：定义 Agent 规范

创建 agents/13-illustrator.md：

# Agent #13 技术插画师

## 角色定位
- **类型**：general-purpose
- **层级**：Spoke（主编排的子 Agent）

## 职责
- 根据章节内容生成技术插图
- 将插图输出为 Mermaid 或 SVG 格式
- 确保插图风格与全书一致

## 输入（File Pointers）
- `chapters/draft/chXX-draft.md`  ← 待配图章节
- `output/memory/style-guide.md`   ← 风格规范
- `output/assets/illustrations/`   ← 参考插图库

## 输出（File Pointers）
- `output/assets/illustrations/chXX-*.mermaid` ← 插图文件
- `output/assets/illustrations/chXX-*.svg`     ← 备选格式

## 工作约束
- 插图风格必须与 style-guide 一致
- 每个章节至少 1 张核心插图
- 优先使用 Mermaid（便于渲染）

10.3.2 第二步：在主编排中注册

修改 agents/01-orchestrator.md：

## Agent 注册表

| Agent # | 名称 | 类型 | 层级 | Phase |
|---------|------|------|------|-------|
| 0 | 主编排 | orchestrator | Hub | 全部 |
| 1 | 架构师 | explore | Spoke | Phase 1 |
| ... | ... | ... | ... | ... |
| 12 | 质检员 | general-purpose | Spoke | Phase 5 |
| 13 | 技术插画师 | general-purpose | Spoke | Phase 3 |

10.3.3 第三步：在 Phase 3 中集成

在章节写作流水线中添加插图步骤：

## Phase 3 章节写作流程（修改后）

每章四步：
1. 研究员调研 → 输出研究报告
2. 作家写作 → 输出章节草稿
3. 技术插画师配图 → 输出插图文件 ← 新增
4. 三审并行 → 输出审查报告

10.4 定制化写作流程

10.4.1 单人模式

如果你是个人作者，不需要多 Agent 协作？

方案：简化为主编排 + 作家

主编排（你）
    ↓ 读取 outline.md, style-guide.md
作家（你）
    ↓ 输出章节草稿
三审（你）
    ↓ 输出审查报告

Scriptorium 提供了单人模式配置，可以在配置文件中选择激活哪些 Agent。

10.4.2 小团队模式

如果是 2-3 人的小团队？

方案：

  • 保留主编排（统筹）
  • 保留研究员 + 作家（核心写作）
  • 保留 R1/R2/R3（质量保障）
  • 可选：添加插画师

10.4.3 大型出版模式

如果是出版社级别的生产？

方案：

  • 保留完整 Agent 链
  • 添加更多专业化 Agent：
    • 版权审查员
    • 市场分析师
    • 多语言翻译 Agent
  • 添加人工审核节点

10.5 场景化定制

10.5.1 API 文档写作

用 Scriptorium 来写 API 文档？

# api-docs-style.yaml
style-guide:
  code-first: true
  include-request-response: true
  include-error-codes: true
  swagger-markdown: true

glossary:
  endpoint: 端点
  parameter: 参数
  payload: 请求体

metaphor-registry:
  API: 门卫
  endpoint: 门口
  authentication: 钥匙

10.5.2 教程写作

用 Scriptorium 来写交互式教程？

# tutorial-style.yaml
style-guide:
  include-exercises: true
  include-quizzes: true
  difficulty-indicators: true
  time-estimates: true

glossary:
  concept: 核心概念
  exercise: 练习
  solution: 参考答案

10.5.3 论文写作

用 Scriptorium 来写学术论文？

# paper-style.yaml
style-guide:
  academic-voice: true
  citation-format: APA
  abstract-required: true
  peer-review-stages: 3

glossary:
  methodology: 方法论
  hypothesis: 假设
  finding: 发现

10.6 未来展望

Scriptorium 还在不断进化。以下是一些可能的发展方向：

10.6.1 多模态输出

当前：主要输出 Markdown/HTML

未来可能：

  • 音频书生成（Text-to-Speech）
  • 视频教程生成（结合动画）
  • 交互式网页应用

10.6.2 协作增强

当前：单项目串行写作

未来可能：

  • 多项目并行管理
  • 团队成员实时协作
  • 云端协作支持

10.6.3 智能化升级

当前：规则驱动的 Agent

未来可能：

  • 基于 LLM 的智能调度优化
  • 自动检测内容质量
  • 预测性写作建议

10.7 快速上手清单

想搭建自己的 Scriptorium？以下是快速清单：

基础配置

  • ⬜ 克隆 Scriptorium 框架
  • ⬜ 阅读 README.md 了解架构
  • ⬜ 配置主编排的模型参数
  • ⬜ 测试基础 Agent 是否工作

定制化

  • ⬜ 定义你的 style-guide.md
  • ⬜ 定义你的 glossary.md
  • ⬜ 定义你的 metaphor-registry.md
  • ⬜ 按需添加/修改 Agent

流程优化

  • ⬜ 运行第一个小项目测试
  • ⬜ 收集反馈，调整 Agent 规范
  • ⬜ 优化 File Pointers 配置
  • ⬜ 建立团队的使用规范
