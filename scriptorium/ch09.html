9.1 最后一个环节

如果把写书比作拍电影，那么 Phase 1-4 就是：

  • 写剧本（大纲）
  • 建剧组（共享资源）
  • 拍摄（逐章写作）
  • 剪辑（审查修订）

Phase 5 就是最后的上映发行——把胶片变成观众能看到的电影。

9.3 #11 装帧工人

9.3.1 角色定位

装帧工人是"印刷厂"——他把作者的手稿变成精美的成品书。

核心职责：

职责说明
Markdown → HTML格式转换
目录生成自动生成章节目录
样式应用应用 style-guide 定义的样式
交叉引用插入章节间的链接
封面制作生成书籍封面

9.3.2 格式转换规则

Markdown 的每个元素都有对应的 HTML 转换规则：

Markdown 元素HTML 输出
# 标题<h1> 到 <h6>
**粗体**<strong>
*斜体*<em>
```代码 ```<pre><code>
[链接](url)<a href="url">
```mermaid`SVG 图表

9.4 #12 质检员

9.4.1 角色定位

质检员是"出厂检验员"——确保每一本书都符合质量标准。

7 项检查清单：

#检查项检查内容
1ZIP 结构EPUB 压缩包结构是否正确
2XML 有效性XML 文件是否符合规范
3SVG 颜色图表颜色是否合规
4CSS 合规样式表是否有语法错误
5标题一致书名、章标题是否与元数据一致
6封面封面图片是否存在且格式正确
7导航目录链接是否都有效

9.4.2 自动化检查

质检员的检查是程序化的——不是人工抽查，而是自动遍历：

9.5 交付物格式

9.5.1 HTML 网站

静态 HTML 网站，可直接部署到任意 Web 服务器：

output/publish/
└── index.html   ← 入口页面（带目录导航）

特点：

  • 纯静态，无需后端
  • 可在任何浏览器打开
  • 支持离线阅读（需要下载全部文件）

9.5.2 EPUB 电子书

标准的 EPUB 格式，可导入各类阅读器：

output/publish/
└── epub/
    └── book.epub   ← 电子书文件

支持的阅读器：

  • Kindle（需转换）
  • Apple Books
  • Calibre
  • 微信读书（支持 EPUB 导入）

9.7 常见问题处理

9.7.1 Mermaid 图表渲染失败

问题：Mermaid 代码无法渲染成 SVG。

原因：Mermaid 服务未正确配置。

解决：

  1. 检查 Mermaid CDN 是否可访问
  2. 确认图表代码语法正确
  3. 降级为静态图片

9.7.2 链接失效

问题：某些内部链接指向了不存在的章节。

原因：章节编号或文件名变更后未更新链接。

解决：

  1. 重新运行质检检查
  2. 使用相对路径而非绝对路径
  3. 自动化生成链接列表

9.7.3 封面图片问题

问题：封面图片无法显示。

原因：图片格式不受支持或路径错误。

解决：

  1. 使用支持的格式：JPG、PNG、WebP
  2. 确保图片路径正确
  3. 检查图片文件大小（EPUB 有大小限制）

9.8 小结

本章我们了解了发布与装帧的最终流程：

  1. Phase 5 定位：从"手稿"到"成品书"的转换
  2. 装帧工人：Markdown → HTML，自动格式转换
  3. 质检员：7 项程序化检查，确保出厂质量
  4. 交付物：HTML 网站 + EPUB 电子书
  5. 高度自动化：整个 Phase 5 几乎不需要人工介入

经过 Phase 1-5 的流水线，书稿终于变成了可以交付的成品。
