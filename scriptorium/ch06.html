第6章：五阶段流水线

本章目标
  • 理解 Scriptorium 五阶段流水线的整体设计
  • 掌握每个阶段的核心任务和产出物
  • 了解并行执行策略
  • 理解阶段之间的依赖关系

6.1 流水线总览

想象一条汽车生产线：冲压 → 焊接 → 涂装 → 总装 → 检测。每个阶段都是前一个阶段的下游，同时又是下一个阶段的上游。

Scriptorium 的生产流水线也是如此：

flowchart LR P1["Phase 1
大纲定稿"] --> P2["Phase 2
共享资源"] P2 --> P3["Phase 3
逐章写作"] P3 --> P4["Phase 4
统稿审计"] P4 --> P5["Phase 5
装帧发布"] style P1 fill:#bbdefb style P2 fill:#c8e6c9 style P3 fill:#fff9c4 style P4 fill:#ffccbc style P5 fill:#d1c4e9

为什么叫"流水线"？

因为每个阶段都有明确的输入和输出，上一阶段的产出是下一阶段的投入。就像工厂的传送带，零件依次经过各个工位，最终成为成品。

6.2 Phase 1：大纲定稿

6.2.1 目标

在开始写正文之前，先确定"这本书要讲什么"、"按什么顺序讲"。

6.2.2 参与 Agent

Agent职责
#1 架构师分析源码结构，设计章节大纲
#2 读者代言人从读者视角审核大纲
R3 内容审查员审核大纲的敏感性和合规性
用户最终确认大纲

6.2.3 产出物

output/memory/outline.md     ← 章节大纲
output/memory/source-map.md  ← 源码文件→章节映射

6.2.4 Phase 1 的关键决策

章节数量：太多会显得冗余，太少会讲不透彻。Scriptorium 推荐 10~12 章。

章节顺序：遵循"学习曲线"原则——先讲基础概念，再讲高级特性。

每章难度标记：

标记含义示例
⭐入门级第1章认识 Scriptorium
⭐⭐基础级第2章系统架构
⭐⭐⭐中等级第4章 Agent 团队
⭐⭐⭐⭐高级第6章五阶段流水线
⭐⭐⭐⭐⭐专家级第10章搭建你的 Scriptorium

6.3 Phase 2：共享资源构建

6.3.1 目标

在开始写章节之前，先建立"规则手册"——确保全书的一致性。

6.3.2 参与 Agent

主编排 #0 直接执行（不需要调度子 Agent）

6.3.3 产出物

文件说明
style-guide.md写作风格指南
glossary.md术语表
metaphor-registry.md比喻注册表
chapter-summaries.md章节摘要（空模板）
cross-references.md交叉引用表（空模板）

6.3.4 为什么先建共享资源？

类比

想象拍一部多集电视剧。如果每个编剧都按自己的风格写，结果可能是：第1集叫"小明"，第3集又叫"小强"。所以开拍前先统一"人物表"和"风格指南"。

6.4 Phase 3：逐章写作

6.4.1 目标

这是流水线上最核心的阶段——把大纲变成正文。

6.4.2 每章四步流水线

flowchart TB S1["Step 1
研究员调研"] --> S2["Step 2
作家写作"] S2 --> S3["Step 3
三审并行"] S3 --> S4["Step 4
读者评审"] style S1 fill:#e3f2fd style S2 fill:#fff3e0 style S3 fill:#e8f5e9 style S4 fill:#fce4ec

6.4.3 并行执行策略

三章一批，同时推进：

第1批（ch01-ch03）：
  - ch01: 研究 → 写作 → 三审
  - ch02: 研究 → 写作 → 三审
  - ch03: 研究 → 写作 → 三审

第2批（ch04-ch06）：
  ...

第3批（ch07-ch09）：
  ...

第4批（ch10）：
  ...

同批内并行：

  • 同一批的三章，Step 1（研究）可以并行
  • Step 2（写作）可以并行
  • Step 3（三审）可以并行
  • Step 4（读者评审）可以并行

6.4.4 产出物

每章完成后，产出：

  • research/chXX-report.md — 研究报告
  • chapters/draft/chXX-draft.md — 章节草稿
  • reviews/chXX-r1.md — R1 审查报告
  • reviews/chXX-r2.md — R2 审查报告
  • reviews/chXX-r3.md — R3 审查报告
  • reviews/chXX-panel.md — 读者评审报告

6.5 Phase 4：统稿审计

6.5.1 目标

所有章节写完后，进行全书的"最终体检"。

6.5.2 参与 Agent

Agent职责
主编排 #0统筹审计工作
R1 源码审查员抽检代码引用
R2 一致性审查员检查全书一致性
R3 内容审查员审核全书叙事连贯性

6.5.3 审计重点

维度检查内容
术语一致性全书术语是否统一
跨章引用章节之间的引用是否正确
代码准确性抽样检查代码引用的准确性
叙事连贯全书是否有统一的"声音"和"风格"

6.6.1 目标

把 Markdown 转换成可阅读的 HTML 电子书。

6.6.2 参与 Agent

Agent职责

6.6.3 质检项目

质检项说明

6.6.4 产出物

output/publish/ 目录下的静态 HTML 网站，可直接发布或打包为 EPUB。

6.7 流水线的"质检门"

每个阶段结束时，都有一个"质检门"（Quality Gate）：

flowchart LR P["完成"] --> G{"质检门
合格?"} G -->|"通过"| N["下一阶段"] G -->|"不通过"| F["打回修改"] F --> P style G fill:#ffebee,stroke:#f44336 style N fill:#e8f5e9

质检门的作用：

  • 防止不合格的产出进入下一阶段
  • 确保每个阶段的质量可控
  • 避免"欠债"越积越多

6.8 小结

本章我们了解了五阶段流水线：

  1. Phase 1 大纲定稿：确定"讲什么"和"按什么顺序讲"
  2. Phase 2 共享资源：建立全书统一的规则手册
  3. Phase 3 逐章写作：最核心的阶段，每章四步流水线
  4. Phase 4 统稿审计：全书的"最终体检"
  5. Phase 5 装帧发布：Markdown→HTML，交付成品
