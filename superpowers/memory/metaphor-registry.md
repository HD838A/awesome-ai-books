# Superpowers 源码解析：AI 编程助手的超能力框架 比喻注册表

## 概述

本文件管理全书使用的比喻映射关系。每个核心技术概念最多绑定 **一个主比喻**，在全书范围内保持一致。

### 比喻质量标准

一个好的比喻应该满足：
- ✅ **准确性**: 比喻的关键特征与技术概念的关键特征匹配
- ✅ **熟悉度**: 目标读者对比喻本体足够熟悉
- ✅ **可扩展性**: 能延伸到概念的多个方面，不会在某个点上"破裂"
- ✅ **无歧义**: 不会让读者产生错误理解

## 比喻注册表

| 技术概念 | 绑定比喻 | 首次使用章节 | 状态 | 注意事项 |
|----------|----------|-------------|------|----------|
| Superpowers | 编程助手的"装备系统" | ch1 | 活跃 | 想象 RPG 游戏中的装备系统——穿上不同的装备（Skills），你的角色（AI）就获得了不同的能力。注意：不是"升级"而是"装备"，强调可组合性和选择性 |
| Skill | 功能模块 / 工具箱里的工具 | ch1 | 活跃 | 就像乐高积木，每个 Skill 是一个可以独立使用、也可以组合的功能块。注意：Skill 比"插件"更强调"可组合"和"专业分工" |
| Hook | 汽车的"自动启停"功能 | ch2 | 活跃 | 当特定条件满足时（启动汽车），Hook 自动触发（发动机自动启动）。比喻的是"事件触发"而非"手动启动"。注意：Hook 是被动的，必须有触发事件 |
| context injection | 给 AI 递"便签条" | ch2 | 活跃 | 就像你在开会时给同事递一张便签，上面写着"记得提一下那个预算的事"。Superpowers 在会话开始时给 AI 递一张便签，告诉它"你有了超能力"。注意：便签是补充，不是替代原始指令 |
| bootstrap | 电脑开机的"自检"过程 | ch2 | 活跃 | BIOS 开机自检确保一切就绪后才加载操作系统。Superpowers 的 bootstrap 做类似的事情：确保 Skills 系统就绪后才开始工作。注意：bootstrap 是初始化，不是主程序 |
| subagent | 派出去办事的"外包团队" | ch5 | 活跃 | 你（主会话）接到一个项目后，把具体任务外包给不同的 subagent（外包团队），每个团队只知道自己需要完成的任务，不知道项目全貌。这样既高效又不会"思维混乱"。注意：外包团队不能直接和其他团队（其他 subagent）沟通，必须通过你这个总包 |
| two-stage review | 论文审稿流程 | ch5 | 活跃 | 论文先要通过"创新性审查"（是否符合领域前沿），再通过"技术审查"（实验是否严谨）。Subagent-Driven Development 先做 Spec Review（设计对不对），再做 Code Quality Review（代码好不好）。注意：顺序很重要——如果先批评代码写法，但发现设计本身就是错的，那代码写得再好也没用 |
| HARD-GATE | 工地的"安全门禁" | ch4 | 活跃 | 工人必须佩戴安全帽才能进入工地，无论你觉得多么简单的工作。HARD-GATE 要求必须通过设计评审才能开始实现，无论你觉得需求多么明确。注意：这是强制规则，不是建议 |
| brainstorming | 建筑师的"需求对话" | ch4 | 活跃 | 好的建筑师不会一上来就画图，而是先和你聊：你想在这个空间里做什么？有什么特别的需求？即使你只是说"想要一个舒服的客厅"，他们也会追问"舒服对你意味着什么"——这正是 brainstorming 要做的事情。注意：聊天是为了理解真实需求，不是为了拖延时间 |
| Skill trigger | 魔术棒的"咒语" | ch3 | 活跃 | 对着哈利波特说"Locomotor"他会动，说"Wingardium Leviosa"物体会飘起。对 AI 说"用 brainstorming"或"使用 systematic-debugging"，对应的 Skill 就会被激活。注意：咒语要准确，说错了 AI 听不懂 |
| systematic debugging | 医生的"诊断流程" | ch7 | 活跃 | 好医生不会一上来就开刀，而是先问诊、做检查、排除可能性。系统化调试也是如此：收集信息、形成假设、验证假设、定位根因。注意：不要学"百度求医"式调试——随便试试，不行就换方案 |
| TDD | 先写"考试题目"再做"答案" | ch8 | 活跃 | 想象考试时先发答案再出题目？TDD 就是让你先写出"这个函数应该能正确计算 2+2=4"，然后再去实现这个函数。这样你就知道什么是对、什么是错，不会自己骗自己。注意：题目要出得准，不能故意出很简单或故意出自己已经会的 |
| plugin | 手机的"应用" | ch1 | 活跃 | 插件就像手机应用——下载安装后，手机就多了这个应用的功能。Superpowers 是一个让 AI 编程助手"更强大"的插件。注意：安装插件不会改变手机本身，而是扩展了它的能力 |
| platform adapter | 旅行时的"翻译官" | ch9 | 活跃 | 你不会说日语，但需要和日本人交流。你雇了一个翻译官，他能理解你的意思，用日语表达给日本人听，再把日本人的回应翻译给你。platform adapter 就是 Superpowers 和不同 AI 平台之间的"翻译官"。注意：翻译官本身不创造内容，只是转换表达方式 |

## 废弃比喻记录

| 原比喻 | 废弃原因 | 替代比喻 | 废弃章节 |
|--------|----------|----------|----------|
| Skill 像"App" | App 容易让人联想到移动应用商店的购买模式，暗示 Skill 是现成的商业产品 | 功能模块 / 工具箱里的工具 | ch1 |
| Hook 像"钩子" | "钩子"让人联想到物理上的挂钩，容易误解为"挂在某处等待"，忽视了事件触发性 | 汽车的"自动启停"功能 | ch2 |
| subagent 像"克隆人" | 克隆人有自己的完整人格和记忆，subagent 不应该有自己的独立"人格" | 派出去办事的"外包团队" | ch5 |

## 比喻使用检查清单

在写作时，引入新比喻前请检查：

1. ☐ 这个技术概念是否已有绑定比喻？（查上表）
2. ☐ 新比喻是否与已有比喻冲突？
3. ☐ 比喻的关键特征是否与概念的关键特征匹配？
4. ☐ 比喻的局限性是否会在后续使用中"破裂"？
5. ☐ 目标读者是否熟悉这个比喻的本体？
