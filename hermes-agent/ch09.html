9.1 什么是轨迹？



9.1.1 定义



轨迹（Trajectory） 是 Agent 执行过程的结构化记录，类似于飞机黑匣子：

┌─────────────────────────────────────────────────────────────────┐

│                      Agent 轨迹示例                              │

├─────────────────────────────────────────────────────────────────┤

│                                                                 │

│  {                                                             │

│    "task_id": "abc123",                                        │

│    "turns": [                                                  │

│      {                                                        │

│        "turn_number": 1,                                       │

│        "user_message": "帮我写一个 hello world",               │

│        "assistant_response": "好的，这是 Python 代码：...",      │

│        "tools_used": ["write_file"],                           │

│        "tokens_used": 1500                                     │

│      },                                                        │

│      {                                                        │

│        "turn_number": 2,                                       │

│        "user_message": "运行一下",                             │

│        "assistant_response": "运行结果：Hello, World!",         │

│        "tools_used": ["terminal"],                            │

│        "tokens_used": 800                                      │

│      }                                                        │

│    ]                                                          │

│  }                                                            │

│                                                                 │

└─────────────────────────────────────────────────────────────────┘


9.1.2 轨迹的作用



用途说明

调试复现问题，分析 Agent 决策
优化发现 Token 消耗瓶颈
审计记录 Agent 的所有操作
学习收集高质量轨迹用于训练

9.3 Gateway Event Hooks



9.3.1 HOOK.yaml 格式



name: my-logger

description: "记录所有 Agent 活动"

events:

  - agent:start      # Agent 开始处理

  - agent:step      # 每个工具调用

  - agent:end       # Agent 结束处理

  - session:start   # 会话开始

  - session:end     # 会话结束


9.3.2 handler.py 实现



import json

from datetime import datetime

from pathlib import Path



LOG_FILE = Path.home() / ".hermes" / "activity.log"



async def handle(event_type: str, context: dict):

    """处理每个事件"""

    entry = {

        "timestamp": datetime.now().isoformat(),

        "event": event_type,

        **context

    }

    

    with open(LOG_FILE, "a") as f:

        f.write(json.dumps(entry) + "\n")


9.3.3 可用事件



事件触发时机上下文键

gateway:startupGateway 进程启动platforms
session:start新会话创建platform, user_id, session_id
session:end会话结束platform, user_id
session:reset用户执行 /newplatform, user_id
agent:startAgent 开始处理消息platform, user_id, message
agent:step每个工具调用循环platform, user_id, iteration, tool_names
agent:endAgent 完成处理platform, user_id, response
command:*任意命令执行command, args



9.4 实战：构建日志系统



9.4.1 场景



构建一个记录所有 Agent 活动的日志系统：

用户: 请帮我写一个 Python 脚本

     ↓

Agent: 开始处理

     ↓

Hook: 记录 agent:start 事件

     ↓

Agent: 调用 write_file 工具

     ↓

Hook: 记录 agent:step 事件

     ↓

Agent: 完成

     ↓

Hook: 记录 agent:end 事件


9.4.2 实现



Step 1：创建 Hook 目录

mkdir -p ~/.hermes/hooks/activity-logger


Step 2：创建 HOOK.yaml

name: activity-logger

description: "记录所有 Agent 活动到日志文件"

events:

  - agent:start

  - agent:step

  - agent:end

  - session:start

  - session:end


Step 3：创建 handler.py

import json

from datetime import datetime

from pathlib import Path

from typing import Any



LOG_DIR = Path.home() / ".hermes" / "logs"

ACTIVITY_LOG = LOG_DIR / "activity.jsonl"



class ActivityLogger:

    def __init__(self):

        LOG_DIR.mkdir(parents=True, exist_ok=True)

        self.session_start: dict = {}

    

    def log(self, event: str, context: dict):

        entry = {

            "timestamp": datetime.now().isoformat(),

            "event": event,

            **context

        }

        with open(ACTIVITY_LOG, "a") as f:

            f.write(json.dumps(entry, ensure_ascii=False) + "\n")



_logger = ActivityLogger()



async def handle(event_type: str, context: dict):

    _logger.log(event_type, context)

    _logger.log(event_type, context)




9.5 实战：构建告警系统



9.5.1 场景



当 Agent 执行敏感操作时，发送告警通知：

敏感操作包括：


  • 删除文件
  • 执行 rm 命令
  • 修改配置


9.5.2 实现



Step 1：创建 Hook 目录

mkdir -p ~/.hermes/hooks/security-alert


Step 2：创建 HOOK.yaml

name: security-alert

description: "敏感操作告警"

events:

  - agent:step


Step 3：创建 handler.py

import json

import os

from datetime import datetime

from pathlib import Path



WEBHOOK_URL = os.getenv("ALERT_WEBHOOK_URL")

SENSITIVE_PATTERNS = [

    "rm -rf",

    "delete_file",

    "remove_file",

    "sudo",

    "chmod 777",

]



async def handle(event_type: str, context: dict):

    tool_names = context.get("tool_names", [])

    

    for tool in tool_names:

        for pattern in SENSITIVE_PATTERNS:

            if pattern.lower() in tool.lower():

                await send_alert(context)

                break



async def send_alert(context: dict):

    if not WEBHOOK_URL:

        return

    

    payload = {

        "text": f"⚠️ 敏感操作检测",

        "blocks": [

            {

                "type": "section",

                "text": {

                    "type": "mrkdwn",

                    "text": f"*敏感操作告警*\n\n工具：{context.get('tool_names')}"

                }

            }

        ]

    }

    # 发送 webhook 请求

    import httpx

    async with httpx.AsyncClient() as client:

        await client.post(WEBHOOK_URL, json=payload)

9.6.1 场景



在 Agent 启动时自动执行检查清单：

启动检查：


  • 检查 cron jobs 是否失败
  • 检查内存使用情况
  • 检查网络连接


9.6.2 实现



创建 BOOT.md

# Hermes Agent 启动检查清单




1. Cron 任务状态


检查是否有 cron 任务失败：
bash
hermes cron list
## 2. 内存使用

检查当前内存使用情况：
bash
free -h
## 3. 网络连接

测试关键服务是否可达：
bash

测试 API 连接


curl -s --max-time 5 https://api.anthropic.com/health || echo "API 连接失败"

测试网络连通性


ping -c 1 8.8.8.8 || echo "网络连接异常"
## 4. 待处理任务

检查是否有待处理的任务或提醒。




5. 环境变量


确认关键环境变量已设置：


  • ANTHROPIC_API_KEY
  • HONCHO_API_KEY




如果任何检查失败，请在回复中说明。


💡 提示：BOOT.md 是 Hermes 内置的启动检查功能，不需要额外配置。只要在 ~/.hermes/ 目录创建这个文件，每次 Gateway 启动时都会自动执行。





9.7 轨迹格式规范



9.7.1 标准轨迹 JSON



{

  "version": "1.0",

  "task_id": "abc123",

  "agent_id": "hermes-primary",

  "started_at": "2025-01-15T10:30:00Z",

  "ended_at": "2025-01-15T10:35:00Z",

  "duration_seconds": 300,

  "turns": [

    {

      "turn_number": 1,

      "user_message": "帮我分析这段代码",

      "assistant_response": "好的，让我先看一下代码...",

      "tool_calls": [

        {

          "tool": "read_file",

          "args": {"path": "src/main.py"},

          "result": "文件内容...",

          "duration_ms": 150

        }

      ],

      "tokens_used": 1500,

      "error": null

    }

  ],

  "metadata": {

    "model": "claude-sonnet-4",

    "platform": "cli"

  }

}


9.7.2 字段说明



字段类型说明

task_idstring唯一任务标识
turnsarray所有对话轮次
tokens_usednumberToken 消耗
duration_msnumber耗时（毫秒）
errorstring/null错误信息

9.8.2 分析 Token 消耗



import json



with open("~/.hermes/logs/activity.jsonl") as f:

    total_tokens = 0

    for line in f:

        entry = json.loads(line)

        if "tokens_used" in entry:

            total_tokens += entry["tokens_used"]



print(f"总 Token 消耗: {total_tokens}")


9.8.3 统计工具使用



from collections import Counter



with open("~/.hermes/logs/activity.jsonl") as f:

    tools = Counter()

    for line in f:

        entry = json.loads(line)

        for tool in entry.get("tool_names", []):

            tools[tool] += 1



print(tools.most_common(10))




⭐ 重点回顾



  • 轨迹（Trajectory） 是 Agent 执行过程的完整记录
  • Event Hooks 允许在关键生命周期点执行自定义代码
  • Gateway Hooks 通过 ~/.hermes/hooks/ 目录注册
  • 可用事件包括：agent:start/step/end、session:start/end、命令执行等
  • BOOT.md 是内置的启动检查功能，无需额外配置
