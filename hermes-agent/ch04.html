4.1 为什么 Agent 需要记忆？



4.1.1 没有记忆的 Agent



想象一个没有记忆的客服：

用户：你好，我姓李

Agent：你好，李先生！



用户：我的订单号是 12345，什么时候发货？

Agent：好的，请问您的订单号是？



用户：...我刚才说了啊，12345

Agent：抱歉，我没有之前的对话记录。


这显然是不可接受的用户体验。

文件内容示例

4.2 MemoryStore 核心机制



4.2.1 文件结构



记忆文件使用 § 作为条目分隔符：

# MEMORY.md



§ 项目使用 FastAPI 框架

§ 数据库连接需要先启动 PostgreSQL

§ API 路由在 app/api/ 目录下



§ 用户配置在 config.yaml

§ 常用测试命令：pytest tests/


4.2.2 双状态设计



MemoryStore 维护两组状态：

class MemoryStore:

    """记忆存储（简化版）"""

    

    def __init__(self):

        # 【快照层】系统提示专用，Session 期间不改变

        self._system_prompt_snapshot: Dict[str, str] = {

            "memory": "",  # Session 开始时固定

            "user": ""

        }

        

        # 【实时层】工具操作时更新

        self.memory_entries: List[str] = []

        self.user_entries: List[str] = []


💡 关键设计：快照层在 Session 期间永不改变。这是因为 AI 模型的上下文有"前缀缓存"机制，固定的前缀可以让缓存命中，显著提升性能。



4.2.3 加载与写入流程



# 会话开始时：加载文件 → 生成快照

def load_from_disk(self):

    self.memory_entries = self._read_file("MEMORY.md")

    self.user_entries = self._read_file("USER.md")

    

    # 生成快照，后续只读不写

    self._system_prompt_snapshot = {

        "memory": self._render_block("memory", self.memory_entries),

        "user": self._render_block("user", self.user_entries),

    }




会话中：工具写入 → 立即持久化


def add(self, target: str, content: str):

    self.memory_entries.append(content)

    self.save_to_disk(target)  # 立即写入磁盘




4.3 记忆工具使用



4.3.1 memory 工具概览



memory 工具支持三种操作：

操作作用示例

add添加新记忆{"target": "memory", "action": "add", "content": "..."}
replace替换已有记忆{"target": "memory", "action": "replace", "old_text": "旧内容", "content": "新内容"}
remove删除记忆{"target": "memory", "action": "remove", "old_text": "..."}

4.3.2 添加记忆



# 语法

memory(

    target: str,      # "memory" | "user"

    action: str = "add",

    content: str = "" # 新记忆内容

)


示例场景：

用户：以后遇到 Python asyncio 的问题，优先用 asyncpg 而不是 aiopg



Agent（自动调用 memory 工具）：

┌──────────────────────────────────────┐

│ memory(                              │

│   target="memory",                   │

│   action="add",                     │

│   content="优先使用 asyncpg 而非     │

│   aiopg 处理 PostgreSQL 异步操作"     │

│ )                                    │

└──────────────────────────────────────┘


4.3.3 替换与删除



# 替换：使用唯一子串匹配

memory(

    target="memory",

    action="replace",

    old_text="旧的事实",      # 只要能被唯一匹配的子串即可

    content="新的事实"

)




删除：同样使用子串匹配


memory(

    target="user",

    action="remove",

    old_text="不需要的记忆"

)




4.4 字符限制与安全



4.4.1 为什么需要字符限制？



记忆内容会被注入到系统提示中。系统提示的大小直接影响：

  • AI 模型的上下文窗口占用
  • API 调用的 token 消耗
  • 响应速度


Hermes Agent 为两种记忆设置了硬性限制：

存储默认限制说明

MEMORY.md2,200 字符Agent 对环境的认知
USER.md1,375 字符Agent 对用户的认知

⚠️ 注意：这是字符数而非 token 数。因为不同模型的 tokenization 方式不同，使用字符数更公平。



4.4.2 超出限制怎么办？



当添加新记忆会超出限制时，Agent 需要清理旧记忆：

用户：记一下 ABC 公司成立于 2015 年



Agent：

┌─────────────────────────────────────────────────────────┐

│ ⚠️ 记忆存储已接近上限（2180/2200 字符）                  │

│                                                         │

│ 需要先清理一些过时记忆才能添加新内容。                    │

│                                                         │

│ 当前记忆：                                              │

│ 1. 项目使用 FastAPI 框架                                │

│ 2. 数据库连接需要先启动 PostgreSQL                       │

│ 3. API 路由在 app/api/ 目录下                           │

│ 4. 用户配置在 config.yaml                                │

│ 5. 常用测试命令：pytest tests/                           │

│ ...                                                     │

└─────────────────────────────────────────────────────────┘


4.4.3 注入安全防护



记忆内容最终会被注入到系统提示中，这带来了提示注入攻击的风险。Hermes Agent 做了以下防护：

# memory_tool.py 中的威胁扫描

_MEMORY_THREAT_PATTERNS = [

    # 提示注入

    r'ignore\s+(previous|all|above|prior)\s+instructions',

    r'you\s+are\s+now\s+',

    r'do\s+not\s+tell\s+the\s+user',

    # 敏感数据外泄

    r'curl\s+[^\n]*\$\{?\w*(KEY|TOKEN|SECRET',

    r'wget\s+[^\n]*\$\{?\w*(KEY|TOKEN|SECRET',

    # SSH 后门

    r'authorized_keys',

]




不可见字符检测（防止隐藏注入）


_INVISIBLE_CHARS = {'\u200b', '\u200c', '\u200d', '\ufeff', ...}


💡 提示：如果用户试图通过 memory 工具注入恶意内容，系统会直接拒绝。

4.6 实践：让 Agent 记住你的偏好



4.6.1 场景



你希望 Agent：

  • 叫你"老板"而不是"先生/女士"
  • 回答尽量简洁
  • 代码示例使用中文注释


4.6.2 操作步骤



方法一：直接告诉 Agent

用户：请记住我的偏好：


  • 叫我"老板"
  • 回答要简洁
  • 代码注释用中文




Agent：好的，老板！我已经记住了：


  • 称呼：老板
  • 风格：简洁
  • 注释：中文




（Agent 会自动调用 memory 工具写入 USER.md）


方法二：手动编辑 USER.md

# 直接编辑记忆文件

$ vim ~/.hermes/memories/USER.md




内容示例


§ 用户称呼：老板

§ 回答风格：简洁明了，不废话

§ 代码注释：使用中文

§ 技术栈：Python + React


4.6.3 验证



开启新会话后：

用户：你好



Agent：老板好！有什么需要我帮忙的？




⭐ 重点回顾



  • Hermes Agent 使用文件持久化方案，记忆存储在 MEMORY.md 和 USER.md
  • 双状态设计：快照层用于系统提示（固定），实时层用于工具操作
  • memory 工具支持 add、replace、remove 三种操作
  • 字符限制防止记忆膨胀（MEMORY.md: 2200，USER.md: 1375）
  • 内置注入防护，阻止恶意内容混入系统提示
