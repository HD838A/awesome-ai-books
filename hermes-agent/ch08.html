8.1 什么是上下文工程？



8.1.1 定义



上下文工程（Context Engineering） 是设计和优化 AI 模型输入上下文的技术，包括：

  • 系统提示 — AI 的角色定义和行为指导
  • 上下文注入 — 动态插入的实时信息
  • 历史对话 — 多轮对话的上下文
  • 工具定义 — 可用工具的描述


8.1.2 类比



把 AI 模型想象成一个新员工：

┌─────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────┤

8.2 系统提示的组成



8.2.1 PromptBuilder 架构



Hermes Agent 的系统提示由多个模块组装：

# agent/prompt_builder.py

def build_system_prompt():

    parts = [

        # 1. 基础身份定义

        DEFAULT_AGENT_IDENTITY,

        

        # 2. 记忆快照

        memory_system_prompt,

        user_system_prompt,

        

        # 3. 平台提示

        platform_hints,

        

        # 4. Skill 索引

        skills_index,

        

        # 5. 上下文文件

        .hermes.md 或 HERMES.md,

        

        # 6. 工具定义

        tool_definitions,

    ]

    return "\n\n".join(filter(None, parts))

8.4 上下文注入安全



8.4.1 威胁扫描



上下文文件在注入前会经过安全扫描：

_CONTEXT_THREAT_PATTERNS = [

    # 提示注入

    r'ignore\s+(previous|all|above|prior)\s+instructions',

    r'do\s+not\s+tell\s+the\s+user',

    r'system\s+prompt\s+override',

    

    # 可执行内容

    r'translate\s+.*\s+into\s+.*\s+and\s+(execute|run|eval)',

    

    # 数据外泄

    r'curl\s+[^\n]*\$\{?\w*(KEY|TOKEN|SECRET',

]

8.5 上下文压缩



8.5.1 为什么需要压缩？



模型最大上下文成本

Claude 3.5200K tokens随上下文增长
GPT-4o128K tokens随上下文增长

上下文越长：
  • ✅ 记忆越多
  • ❌ 成本越高
  • ❌ 延迟越高
  • ❌ 效果可能下降（中间丢失问题）


8.5.2 压缩策略



# 记忆插件的生命周期钩子

def on_pre_compress(messages):

    """在压缩前提取关键信息"""

    return extract_key_facts(messages)


策略说明示例

摘要压缩为摘要"用户讨论了 A、B、C"
提取只保留关键实体"项目：X，技术：Y"
剪枝删除低价值消息删除简单问候

8.5.3 记忆的快照模式



如第 4 章所述，Hermes Agent 使用快照模式避免上下文膨胀：

会话开始时：

  MEMORY.md → 快照 → 注入系统提示（固定不变）



会话期间：

  工具写入 → 更新磁盘文件

           → 不更新快照（保持稳定）

⭐ 重点回顾



  • 系统提示由多个模块组装：身份定义、记忆快照、Skill 索引、上下文文件
  • .hermes.md 文件会被自动注入到系统提示，用于项目级约定
  • 所有上下文文件都经过安全扫描，防止提示注入攻击
  • 上下文压缩是控制成本和延迟的关键策略
  • 快照模式让记忆在会话期间保持稳定，避免重复注入
