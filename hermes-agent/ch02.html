2.2 AIAgent 主循环：分解为三个步骤



Hermes Agent 的核心是一个循环结构，我们称之为 主循环（Main Loop）。每次用户发送消息，Agent 就会执行一次这个循环。

2.2.1 步骤一：消息循环（Message Loop）



在调用 AI 模型之前，Agent 需要做好准备工作：

  • 加载对话历史：从 messages 列表中读取之前的对话
  • 获取记忆上下文：从 Memory Manager 那里获取之前存储的信息
  • 组装系统提示词：把系统提示词、记忆、Skill 信息等组装在一起


# run_agent.py - 简化示意

async def run_conversation(self, user_message, conversation_history=None):

    messages = list(conversation_history) if conversation_history else []

    messages.append({"role": "user", "content": user_message})

    

    # 获取记忆上下文（ephemeral，不会改变 messages 列表本身）

    _ext_prefetch_cache = self._memory_manager.prefetch_all(user_message) or ""


关键点：消息循环不仅仅是"把用户消息加到列表里"，还包括：

  • 上下文压缩：当对话太长时，压缩历史消息
  • 记忆注入：把记忆系统返回的内容插入到上下文中
  • 插件钩子：允许插件在调用模型前修改上下文


2.2.2 步骤二：工具调用（Tool Invocation）



这是 Agent 与外界交互的核心环节。流程如下：

# 主循环核心代码简化

while api_call_count < self.max_iterations:

    api_call_count += 1

    

    # 1. 调用 AI 模型

    response = await self._call_model(api_messages)

    

    # 2. 检查是否有工具调用

    if response.tool_calls:

        # 3. 执行工具

        for tool_call in response.tool_calls:

            tool_result = await handle_function_call(tool_call)

            messages.append(tool_result)  # 添加工具结果到历史

        continue  # 继续循环，看看模型是否还有更多工具调用

    

    # 4. 没有更多工具调用，返回最终响应

    return response.content


工具调用的三种情况：

情况说明示例

直接回答模型可以直接回答，不需要工具"今天天气怎么样？"→ 直接从记忆中回答
单次工具需要调用一个工具"帮我搜索最新的 AI 新闻"→ 调用 web_search
多次工具需要按顺序调用多个工具"帮我写一个 Python 函数，然后运行测试"→ write_file + execute_code

2.2.3 步骤三：响应处理（Response Handling）



当模型说"我完成了"，Agent 需要：

  • 整理响应：格式化模型输出
  • 保存轨迹：记录这次对话的完整过程（用于调试和分析）
  • 更新记忆：把重要的信息存入记忆系统
  • 返回结果：把最终响应返回给用户

2.4 模型适配器：支持多种 AI 模型



Hermes Agent 不绑死于某一个 AI 模型。它通过适配器模式支持多种模型：

适配器支持的模型说明

anthropic_adapter.pyClaude 系列原生支持 Claude Messages API
openai_adapter.pyGPT-4、GPT-5 等OpenAI 兼容接口
codex_responses.pyCodex、GPT 模型使用 Responses API

Anthropic 适配器的核心功能



# agent/anthropic_adapter.py - 核心功能

class AnthropicAdapter:

    def __init__(self, api_key, base_url=None):

        self.client = anthropic.Anthropic(api_key=api_key, base_url=base_url)

    

    def call(self, messages, tools=None, model="claude-sonnet-4-20250514"):

        return self.client.messages.create(

            model=model,

            messages=messages,

            tools=tools,

            max_tokens=8192  # Claude 需要指定最大 token 数

        )


适配器的职责：

  • 格式转换：把通用格式转换成特定 API 的格式
  • 认证处理：处理各种认证方式（API Key、OAuth 等）
  • 错误处理：针对不同 API 的错误做适配
  • 特性支持：如 Claude 的 thinking、prompt caching 等




2.5 上下文管理机制（预告）



Hermes Agent 的上下文管理非常精细，包括：

  • 系统提示词组装：prompt_builder.py
  • 上下文压缩：当对话太长时，压缩历史消息
  • 记忆注入：把记忆信息插入到上下文
  • 提示词注入防护：防止恶意的提示词注入攻击


⚠️ 注意：上下文管理是 Hermes Agent 的核心能力之一，但内容较多，我们会在第 8 章详细讲解。





2.6 Agent 身份（Soul）：Soul.md 简介



你有没有想过，为什么同一个 AI 模型，在不同项目里表现得像不同的"人"？

这背后的秘密就是身份配置（Soul）。

Soul 是什么？



Soul 是定义 Agent 身份和性格的配置文件，通常命名为 SOUL.md 或 soul.md。

# soul.md 示例




身份设定


你叫小明，是一个热情、幽默的编程助手。

你喜欢用生动的比喻来解释技术概念。




语言风格



  • 喜欢用"咱们"、"咱们一起"
  • 遇到问题时会说"别慌，这个很好解决"
  • 代码写得好时会夸"写得真漂亮！"





专业领域



  • Python 编程
  • Web 开发
  • AI 应用


Soul 如何工作？



# agent/prompt_builder.py

def load_soul_md(cwd):

    """加载 SOUL.md 文件"""

    soul_path = cwd / "SOUL.md"

    if soul_path.exists():

        return soul_path.read_text()

    return ""



def build_system_prompt():

    soul = load_soul_md(cwd)

    # 把 Soul 内容注入到系统提示词中

    return f"{DEFAULT_IDENTITY}\n\n{soul}\n\n{MEMORY_GUIDANCE}"


💡 提示：Soul 就像给 Agent "注入灵魂"。同一个模型，加上不同的 Soul，就会表现出完全不同的性格。





2.7 异步编程基础预告



细心的你可能注意到了，在代码中有很多 async 和 await。这是 Python 的异步编程特性。

为什么需要异步？



想象一下：

同步：你去银行办业务，必须站在窗口前等业务员处理完，哪怕他只是在电脑上查个东西，你也得干等着。


>

异步：你去银行办业务，业务员说"您稍等，我查一下"，然后去忙别的。你在等候区可以刷手机、喝水。查到结果后，业务员会叫你。



异步编程让 Agent 在等待 AI 模型响应或执行工具时，可以做其他事情，从而大大提高效率。

# 同步版本（假想）

def run():

    response = call_api()  # 这行会阻塞 2-3 秒

    print(response)




异步版本（实际使用）


async def run():

    response = await call_api()  # 这行会等待，但不阻塞其他代码

    print(response)


💡 提示：你不需要成为异步专家才能使用 Hermes Agent。但如果你想深入理解它的内部机制，建议学习 Python 的 asyncio 库。





⭐ 重点回顾



  • AIAgent 主循环分为三个步骤：消息循环 → 工具调用 → 响应处理
  • 消息流转：用户消息 → 模型调用 → 工具执行 → 模型再次调用 → 最终响应
  • 适配器模式：通过适配器支持多种 AI 模型（Claude、GPT 等）
  • Soul（灵魂）：通过 SOUL.md 文件定义 Agent 的身份和性格
  • 上下文管理：包括提示词组装、记忆注入、上下文压缩等复杂机制
