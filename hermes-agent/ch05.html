学完这章，你将能够：

  • 了解 Hermes Agent 的 8 个记忆插件及其适用场景

5.1 为什么需要记忆插件？



5.1.1 内置记忆的局限



在第 4 章中，我们学习了 Hermes Agent 的内置记忆系统（MEMORY.md / USER.md）。它有以下特点：

优点局限

✅ 零依赖，简单可靠❌ 仅支持手动写入
✅ 无需网络请求❌ 无法自动从对话中提取信息
✅ 存储在本地文件❌ 不支持语义搜索
✅ 字符限制防止膨胀❌ 无法跨会话自动关联信息

5.1.2 插件化解决方案



Hermes Agent 引入了插件化记忆系统：

┌────────────────────────────────────────────────────────────────┐

│                      MemoryManager                             │

│                   （记忆管理器，中心协调）                       │

├────────────────────────────────────────────────────────────────┤

│                                                                │

│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │

│  │ Builtin     │    │ Honcho       │    │ Hindsight    │ ...  │

│  │ Memory      │ +  │ Memory       │ +  │ Memory       │       │

│  │ (内置)       │    │ (插件)        │    │ (插件)        │       │

│  └──────────────┘    └──────────────┘    └──────────────┘       │

│                                                                │

│  【规则】Built-in 永远启用，只允许一个外部插件同时运行            │

└────────────────────────────────────────────────────────────────┘


💡 关键设计：外部插件只能添加功能，不能替换内置记忆。两种记忆可以同时生效。





5.2 MemoryProvider 接口



5.2.1 接口概述



所有记忆插件都需要实现 MemoryProvider 抽象基类：

# agent/memory_provider.py（简化版）

class MemoryProvider(ABC):

    """记忆提供者抽象基类"""

    

    @property

    @abstractmethod

    def name(self) -> str:

        """插件名称，如 'honcho'、'mem0'、'hindsight'"""

    

    @abstractmethod

    def is_available(self) -> bool:

        """检查插件是否可用（如是否配置了 API Key）"""

    

    @abstractmethod

    def initialize(self, session_id: str, kwargs) -> None:

        """初始化插件（如连接数据库、建立会话）"""

    

    @abstractmethod

    def get_tool_schemas(self) -> List[Dict]:

        """返回该插件暴露给 AI 的工具"""


5.2.2 核心生命周期方法



方法调用时机作用

is_available()Agent 启动时检查是否满足使用条件
initialize()Agent 初始化建立连接、创建资源
system_prompt_block()组装系统提示时返回静态提示文本
prefetch()每次 API 调用前拉取相关记忆上下文
sync_turn()每次对话轮次后同步对话到后端
shutdown()Agent 关闭时清理资源

5.2.3 可选钩子



钩子触发时机用途

on_turn_start()每轮对话开始统计、作用域管理
on_session_end()会话结束时提取总结性记忆
on_pre_compress()上下文压缩前提取关键信息
on_delegation()委派任务时观察子 Agent 工作

5.4 插件详解



5.4.1 Honcho — AI-native 用户建模



一句话介绍：像朋友一样了解你的用户。

核心能力：

工具作用成本

honcho_profile获取用户核心画像（事实列表）低
honcho_search语义搜索用户记忆中
honcho_context问答式查询（LLM 推理）高
honcho_conclude写入结论性记忆中

使用场景：

用户：我在上海工作，经常加班到很晚



Agent：明白，我会记住你是在上海的"夜猫子"。



（自动调用 honcho_conclude 写入：

"用户在上海工作，经常加班到很晚"）


配置：

# ~/.hermes/config.yaml

memory:

  provider: honcho



honcho:

  api_key: ${HONCHO_API_KEY}  # 从环境变量读取


5.4.2 Mem0 — 智能事实提取



一句话介绍：让 AI 自动记住重要的事情。

核心特点：

  • 自动提取：不需要手动调用工具，AI 自动识别并存储重要信息
  • 语义搜索：用自然语言搜索记忆，如"用户上次提到的项目叫什么？"
  • 自动去重：相同事实不会重复存储


工作原理：

┌─────────────────────────────────────────────────────────────┐

│  用户：我的公司叫 XYZ，主要做 SaaS 产品                       │

└─────────────────────────────────────────────────────────────┘

                            │

                            ▼

┌─────────────────────────────────────────────────────────────┐

│                    Mem0 Provider                           │

│  1. 识别实体："XYZ公司"、"SaaS产品"                         │

│  2. 提取关系：用户 → 所属 → XYZ公司                          │

│  3. 存储到向量数据库                                        │

└─────────────────────────────────────────────────────────────┘

                            │

                            ▼

┌─────────────────────────────────────────────────────────────┐

│  后续搜索："用户在哪工作？"                                  │

│  → 找到：XYZ公司（相关度 0.95）                              │

│  → 返回：用户在 XYZ 公司工作                                │

└─────────────────────────────────────────────────────────────┘


配置：

# ~/.hermes/config.yaml

memory:

  provider: mem0



mem0:

  api_key: ${MEM0_API_KEY}


5.4.3 Hindsight — 知识图谱记忆



一句话介绍：像大脑一样用关系网络记住知识。

核心特点：

  • 知识图谱：不是简单的列表存储，而是实体和关系构成的网络
  • 实体解析：识别"苹果"是水果还是公司
  • 多策略检索：结合关键词、向量、时间等多维度检索


知识图谱示例：

┌─────────────────────────────────────────────────────────────┐

│                    知识图谱                                  │

│                                                             │

│    [用户] ──→ 属于 ──→ [XYZ公司]                             │

│      │                  │                                  │

│      │ 担任             从事                                │

│      ▼                  ▼                                  │

│  [李明]            [SaaS产品开发]                            │

│      │                                                       │

│      │ 使用                                                         │

│      ▼                                                       │

│  [Python] ──→ 擅长 ──→ [Web开发]                             │

└─────────────────────────────────────────────────────────────┘


配置：

# ~/.hermes/config.yaml

memory:

  provider: hindsight



hindsight:

  api_key: ${HINDSIGHT_API_KEY}


5.4.4 Holographic — 本地隐私优先



一句话介绍：数据不出本地的记忆系统。

核心特点：

  • 完全本地：使用 SQLite 存储，无需网络
  • FTS5 搜索：基于 SQLite 的全文搜索
  • 信任评分：每个事实都有可信度评分
  • HRR 检索：Holographic Representation，组合式记忆检索


适用场景：

  • 🚫 无法使用外部服务的数据敏感环境
  • 🏢 企业内网环境
  • 🔒 对数据隐私有严格要求


配置：

# ~/.hermes/config.yaml

memory:

  provider: holographic




无需额外配置，数据存在本地 SQLite

5.6 安装与配置



5.6.1 安装步骤



Step 1：安装插件

# 通过 hermes CLI 安装

hermes plugins install memory honcho




或手动安装依赖


pip install honcho-ai


Step 2：配置插件

# 交互式配置向导

hermes memory setup




或手动编辑配置


vim ~/.hermes/config.yaml


Step 3：验证安装

hermes doctor --check memory


5.6.2 完整配置示例



# ~/.hermes/config.yaml



memory:

  # 选择一个外部插件（只能选一个）

  provider: honcho

  

  # 内置记忆仍然启用

  builtin:

    enabled: true

    memory_char_limit: 2200

    user_char_limit: 1375




Honcho 配置


honcho:

  api_key: ${HONCHO_API_KEY}

  # 或使用自托管

  baseUrl: http://localhost:8080

  

  # 检索模式

  recall_mode: hybrid  # context | tools | hybrid

  

  # 上下文注入频率

  injection_frequency: every-turn


5.6.3 切换插件



如果想换插件，只需要修改配置：

memory:

  provider: mem0  # 从 honcho 切换到 mem0


⚠️ 注意：切换插件后，之前存储的记忆不会自动迁移。如果需要迁移，请参考各插件的迁移文档。

⭐ 重点回顾



  • MemoryProvider 接口定义了所有记忆插件的规范，包括生命周期方法和工具暴露
  • Hermes Agent 提供 8 个官方记忆插件，覆盖云端、本地、自动、手动等不同需求
  • Honcho 擅长用户建模和 Dialectic Q&A，Mem0 擅长自动提取，Holographic 擅长本地隐私
  • 内置记忆永远启用，外部插件是补充而非替代
  • 只能同时使用一个外部插件，通过 memory.provider 配置切换
